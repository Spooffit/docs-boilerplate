# Document architecture

1. Read the current architecture overview and relevant confirmed requirements and ADRs.
2. Distinguish observed architecture, a proposed option and an approved decision.
3. For a new choice, start with `docs/templates/adr.md`; describe constraints, alternatives, tradeoffs and consequences.
4. Ask for an explicit decision when alternatives have not been resolved. Never assign 'Accepted' to a speculative ADR.
5. Update diagrams, links and adjacent standards only when their ownership calls for it.
6. Run documentation validation and identify evidence gaps in the final summary.
