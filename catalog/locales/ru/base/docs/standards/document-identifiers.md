# Стабильные идентификаторы документов

Каждая страница Markdown в каталоге docs/ должна иметь уникальный устойчивый `id` в YAML-frontmatter. Генератор присваивает начальным страницам детерминированные идентификаторы. При переименовании или переносе документа сохраняйте старый ID: путь файла и идентификатор решают разные задачи.

Новой странице назначайте уникальный ID по правилам существующего каталога. У документа также должны быть понятный заголовок и имя файла в kebab-case. Не выводите из документационного ID идентификатор бизнес-функции, дату, утверждение или выдуманный глобальный номер.

CLI проверяет наличие, синтаксис и уникальность ID в docs/. Он не устанавливает факт организационного согласования. Обычный атрибут `status` отражает состояние документа, **а не утверждение бизнес-владельцем**. Отдельной системы статусов согласования в шаблоне нет.
