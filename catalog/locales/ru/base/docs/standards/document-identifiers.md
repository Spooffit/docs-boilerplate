# Устойчивые идентификаторы документов

Каждая Markdown-страница в `docs/` имеет уникальное и неизменяемое поле `id` в YAML frontmatter. Генератор назначает детерминированные идентификаторы всем исходным страницам. Сохраняйте исходный `id` при переименовании или переносе: путь к файлу и его идентификатор имеют разное назначение.

Для новой страницы назначайте уникальный `id` в принятом формате. Читаемый заголовок и имя файла в kebab-case остаются обязательными. Не выводите из `id` идентификатор бизнес-функции, дату, решение о согласовании или вымышленную сквозную нумерацию.

CLI проверяет наличие, синтаксис и уникальность `id` среди всех страниц `docs/`. Это не означает, что организация согласовала содержимое. Обычное поле `status` обозначает стадию подготовки или сопровождения документа, **а не** бизнес-согласование. Отдельная система статусов утверждения не предусмотрена.
