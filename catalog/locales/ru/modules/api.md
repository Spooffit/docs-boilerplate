# Контракты API

## Область и источник

Опишите реально существующие публичные интерфейсы и их владельцев. Ссылайтесь на принятые OpenAPI, схемы, исходники и версии. Не создавайте фиктивные endpoint.

## Совместимость

Фиксируйте формат запроса и ответа, правила ошибок, авторизацию, изменения контракта и обратную совместимость **в соответствии с реальным API**.

## Проверка

Записывайте фактически выполненные контрактные и интеграционные тесты. Не объявляйте спецификацию доказательством работающего сервера.

Если публичного API нет, оставьте документ черновиком без вымышленных маршрутов.
