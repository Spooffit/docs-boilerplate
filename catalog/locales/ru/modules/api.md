# Проектирование API

## Потребители и ответственность

Назовите реальных потребителей, способы передачи данных и границы ответственности.

## Контракты

Если существует основной контракт API, например OpenAPI или другая принятая схема обмена, добавьте на него ссылку. Не придумывайте машиночитаемый контракт и не создавайте конкурирующую копию в Markdown.

## Совместимость клиентов (при необходимости)

Для реальных потребителей зафиксируйте требования к совместимости, заголовкам и обработке ошибок. Отдельный профиль `http-contracts` выбирается по желанию и не подключается автоматически при выборе этого документационного модуля.

## Совместимость и версии

Опишите реальную политику проекта по версиям, устареванию и управлению изменениями.

## Аутентификация, авторизация и ошибки

Опишите принятые механизмы и семантику ошибок со ссылками на основные контракты.

## Проверка

Перечислите проверки контрактов и тесты со стороны потребителей, которые действительно выполняются.
