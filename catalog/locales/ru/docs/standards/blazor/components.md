# Компоненты Blazor и состояние интерфейса

**Применяется к реальным приложениям Blazor.** Не навязывает render mode, библиотеку UI или обязательную архитектуру управления состоянием.

## Состояние и жизненный цикл

Назначайте владельца редактируемого состояния и различайте параметры, локальное состояние, данные API и кэш. Учитывайте порядок OnInitialized/OnParametersSet, повторные render и disposal. Не создавайте независимые копии одного авторитетного состояния без необходимости.

## Взаимодействие и API

Отличайте локальный ввод, отправленный запрос и подтверждённый сервером результат. Обрабатывайте загрузку, пустое состояние, ошибки, отмену, неизвестный исход и запрет повторной отправки там, где это важно.

## Производительность

Избегайте лишних вызовов API и тяжёлых вычислений при каждом render. При необходимости учитывайте виртуализацию, key, стабильную идентичность элементов и отмену устаревших задач.

## Конкуренция действий

При пересечении запросов проверяйте актуальность ответа перед применением к UI; нельзя показывать устаревшие данные как последние. Не предполагайте, что Dispose мгновенно отменит серверную операцию.

## Проверка

Компонентные тесты проверяют наблюдаемое поведение в рендерере, а браузерные — фокус, клавиатуру, JavaScript, маршрутизацию и реальную сеть. API-контракт проверяйте отдельно.
