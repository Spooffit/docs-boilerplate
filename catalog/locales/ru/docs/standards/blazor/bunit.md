# Компонентное тестирование Blazor через bUnit

**Применяется к Blazor, явно выбравшему bUnit.** Это библиотека компонентных тестов, не настоящий браузер и не интеграция backend.

## Граница компонентного теста

Проверяйте видимый результат, доступность кнопок, сообщения, навигацию и callbacks, а не приватные поля. Учитывайте загрузку, ошибки, отмену, пустое состояние и переходы. Мокированный API не доказывает работу реального сервера.

## Изоляция и асинхронность

Создавайте отдельный TestContext для теста, регистрируйте только необходимые сервисы и корректно освобождайте компоненты. Вызывайте реальные click/change/submit вместо приватных обработчиков. Сравнивайте семантическую разметку через MarkupMatches, если HTML действительно важен.

Для асинхронного обновления применяйте WaitForAssertion/WaitForState с ограниченными timeout. Не помещайте мутацию внутрь повторяемого assertion. Управляйте TaskCompletionSource для гонок вместо произвольных задержек.

Явно задавайте ожидания JS interop. Поддельный IJSRuntime доказывает вызов из .NET, но не исполнение JavaScript в настоящем браузере.

## Размещение и архитектура

При выбранной FSD группируйте тесты по владельцам поведения в существующих слоях; не навязывайте FSD всем проектам. Различайте тест компонента, тест HTTP-адаптера и интеграционный/E2E сценарий.

## Проверка в браузере

Реальный браузер нужен для фокуса, клавиатуры, JS-контролов, глубокой ссылки, загрузок, CORS/cookies/CSRF и взаимодействия отдельно размещённых UI/API. Playwright может быть выбран, но не является обязательным.

## Совместимость тестового раннера

Проверяйте поддержку конкретной пары bUnit и тестового фреймворка. Документированные интеграции включают xUnit, NUnit и MSTest; **не считайте TUnit поддержанным без проверенного примера и версий пакетов**.

Источники: [bUnit](https://bunit.dev/docs/getting-started/writing-tests.html), [асинхронные проверки](https://bunit.dev/docs/verification/async-assertion.html), [JS interop](https://bunit.dev/docs/test-doubles/emulating-ijsruntime.html).
