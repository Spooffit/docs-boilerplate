# Соглашения для компонентов MudBlazor

**Применяется к:** приложениям Blazor, явно использующим MudBlazor. Выбор MudBlazor требует Blazor, но не задаёт модель размещения.

## Выбор компонентов и состояние

- Предпочитайте публичные компоненты и API MudBlazor, документированные для **действительно установленной версии**. Не опирайтесь на внутренние CSS-классы и недокументированные детали.
- Разделяйте данные, редактирование, загрузку и подтверждённое состояние. Не путайте локальную валидацию с подтверждённой сервером записью.
- Для форм проверяйте момент запуска валидации (изменение, отправка или явный вызов) и отображение ошибок пользователю.
- Для таблиц данных явно определяйте серверные контракты пагинации, сортировки и фильтрации, не предполагая, что локальные операции подходят большим наборам.
- Сохраняйте модульную композицию UI, но не оборачивайте каждый стандартный компонент бессмысленной прокладкой приложения.

## Темы и доступность

- Последовательно используйте токены темы для отступов, цвета и типографики. Проверяйте контраст, видимость фокуса, подписи, клавиатуру и ошибки.
- При создании обёрток сохраняйте семантическое взаимодействие. Один внешний вид не доказывает доступность.
- Регистрируйте providers и сервисы по установленной версии; документируйте настоящую настройку приложения в проекте вместо навязывания кода запуска-заглушки.

## Тестирование

Компонентные тесты должны проверять наблюдаемое поведение и сообщения валидации. Для реальной клавиатуры, overlay, фокуса и адаптивного взаимодействия нужны браузерные тесты.
