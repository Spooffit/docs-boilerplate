# Проверка HTTP-контрактов и совместимости

**Применяется, если:** у HTTP API есть потребители либо обязательства по совместимости.

## Источник контракта

Укажите опубликованный интерфейс, его версию и поведение проверяемого развёртывания. OpenAPI может быть авторитетным, если это принято проектом. Пример старого контроллера не доказывает поведение сервера.

Проверяйте методы, пути, типы, обязательность и null, ошибки, статусы, заголовки, права и сериализацию. Не создавайте endpoint и DTO ради заполнения документации.

## Анализ изменений

Учитывайте ограничения маршрутов, значения query по умолчанию, новые обязательные поля, неизвестные значения enum, различие отсутствующего поля и null, точность чисел, даты, коллекции, content type, пагинацию, аутентификацию и ошибки.

## Доказательства и ввод изменений

Связывайте выбранные версии сервера и потребителей, поддерживаемые комбинации и фактический порядок развёртывания. План тестов и проверка схемы ещё не означают совместимости.

## Проверка

Исполняйте контрактные и интеграционные проверки через настоящую сериализацию и транспорт. Отделяйте реально выполненное от непроверенного.
