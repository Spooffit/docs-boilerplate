# Необязательная прямая привязка HTTP DTO к UI-формам

**Применяется, когда:** профиль `ui-direct-dto-forms` явно выбран для UI, использующего HTTP-контракт и подходящие типы API request DTO. Типы может предоставлять существующий клиентский инструментарий проекта. **Профиль задаёт применение модели состояния формы, а не способ генерации клиентского кода или типов.** Требует базовый [HTTP-контракт](../http/client-contracts.md) и [правила доступных форм](forms-and-accessibility.md), но не требует Blazor, отдельной архитектуры клиентской библиотеки, state framework или нового слоя приложения.

## Прямое редактирование как выбранный вариант

- Для редактируемой формы предпочитайте **сам DTO записи/запроса API** как модель ввода, когда подходят изменяемость, nullability и семантика валидации. Не создавайте параллельный ViewModel и дублирующее отображение свойств по умолчанию.
- Отличайте DTO чтения/ответа от редактируемого DTO запроса. Управляемые сервером ID, временные метки, разрешения, вычисляемые свойства и отсутствующие в контракте обновления поля не должны становиться редактируемыми лишь потому, что есть в ответе.
- Инициализируйте независимое значение формы из реально разрешённых исходных данных. Не привязывайте изменяемую форму прямо к общему объекту кэша, иначе несохранённые правки станут видны другим.
- Соблюдайте контрактные обязательность и различие null/отсутствующего значения. Нормализация HTML-поля и локальная валидация улучшают отклик, но не заменяют серверную валидацию и авторизацию. Не придумывайте значения по умолчанию ради обхода обязательных полей.
- При отправке передавайте только разрешённый контрактом запрос и сохраняйте введённые значения до подтверждения успеха сервером. Явно обрабатывайте загрузку, ошибки полей, временные отказы, отклонение конкурентных изменений/предусловий и неопределённые исходы. Не позволяйте устаревшим ответам перезаписывать новые правки.
- Считайте ETag и другие транспортные метаданные метаданными, а не полями DTO, если публичный контракт прямо не задаёт их как поля. Профиль ETag выбирается независимо.

## Когда прямая привязка DTO небезопасна

Некоторые API-типы неизменяемы, доступны только для чтения, полиморфны или объединяют отображаемые и записываемые поля. Если выбранный DTO не допускает безопасного ввода без нарушения контракта, **не меняйте и не обходите его инварианты**: используйте осознанный адаптер формы или специальный ViewModel, либо измените контракт через утверждённое решение API. Это исключение на основе требований, а не автоматический второй слой моделей для всех форм.

## Проверка

Проверяйте состояния пустой/загружаемой/ошибочной/успешной формы, нормализацию ввода, nullability, отмену, устаревшие ответы, валидацию, доступность, разрешённый payload и конфликты конкурентности. Докажите, что несохранённые правки не меняют общие авторитетные данные и UI показывает успех только после реального ответа API. Это соглашение о документации, **не** генерация интерфейса, компилятор, пакет клиента или заготовка приложения.
