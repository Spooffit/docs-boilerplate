# Прямое использование DTO API в формах

**Опциональный профиль ui-direct-dto-forms.** Применяется к UI с HTTP API и подходящими request DTO. Он определяет использование моделей в форме, но не то, как генерируются DTO, клиенты или исходники.

## Редактирование request DTO

Когда DTO поддерживает безопасную мутабельность, nullable и валидацию, используйте **сам request/write DTO** как модель формы. Не создавайте обязательный второй ViewModel и копирование всех полей.

Read/response DTO могут включать идентификаторы, серверные поля и секреты, которые менять нельзя. Не используйте их как write DTO без проверки. При независимых этапах редактирования, сложной локальной семантике или несоответствии сетевому контракту отдельная модель формы может быть оправданной.

## Где прямое связывание опасно

Не разрешайте массовую запись полей только из-за похожего формата. Сервер остаётся авторитетом для прав и доменных инвариантов. UI должен корректно различать локальную валидацию, отправку и принятый эффект. Профиль не требует Blazor, отдельной клиентской архитектуры или фреймворка управления состоянием.

## Проверка

Тестируйте null, сериализацию реального запроса, запрет изменения серверных полей, ошибки, отмену, конкуренцию и повторные отправки. См. [HTTP-контракты](../http/client-contracts.md) и [доступность форм](forms-and-accessibility.md).
