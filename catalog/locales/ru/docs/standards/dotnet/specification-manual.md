# Самописные спецификации запросов на EF Core

**Применимость:** проекты с выбранными EF Core и самописными спецификациями. Для варианта только с Dapper этот паттерн не применяется. Генератор предоставляет документацию, а не готовую реализацию.

## Область применения и контракт

- Используйте спецификации для осмысленных повторно используемых запросов; не создавайте обёртку для каждого тривиального запроса. Прямой запрос EF Core допустим, если спецификация ничего не упрощает.
- До реализации определите контракт: тип сущности и результата, предикаты, сортировку, пагинацию, проекции, включение связей, отслеживание и владение отменой. Проверяйте входные параметры, не меняйте их после создания.
- Спецификация не выполняет I/O, не изменяет сущности, не вызывает `SaveChanges`, не зависит от `HttpContext` и не прячет авторизацию в необязательных пользовательских флагах.
- Ограничения арендатора и владельца применяйте на доверенной границе доступа к данным независимо от фильтров вызывающего кода. Проверьте правило для каждого пути чтения.

## Композиция выражений

- Стройте переводимые провайдером предикаты `Expression<Func<TEntity, bool>>` или ограниченные преобразования `IQueryable<TEntity>` до материализации. Не переходите незаметно к `IEnumerable`, `Compile()` или `AsEnumerable()`, чтобы выполнять фильтры в памяти.
- Явно задавайте группировку AND/OR. При объединении выражений с разными параметрами корректно заменяйте параметры; `Expression.Invoke` используйте лишь после проверки трансляции конкретным провайдером.
- Не смешивайте повторно используемые предикаты с Include, tracking и пагинацией, если это не часть объявленного полного контракта.
- Перед offset-пагинацией задавайте детерминированный порядок с уникальным дополнительным ключом. Для cursor-пагинации определите стабильный контракт курсора и обработку совпадающих ключей.
- Для общего количества записей сохраняйте нужные фильтры, но не применяйте `Skip`/`Take`. Явно задавайте проекции, чтобы не раскрывать лишние данные.

## Интеграция с EF Core

- Применяйте операции спецификации к запросу провайдера до терминальных методов вроде `ToListAsync` и `CountAsync`. Осознанно выбирайте `AsNoTracking` для чтения и tracking для изменений.
- Определите порядок фильтрации, проекции, сортировки и пагинации; проверяйте полученный SQL. Не предполагайте одинаковую трансляцию LINQ на всех версиях и провайдерах.
- Используйте `DbContext` подходящего жизненного цикла, не запускайте параллельные операции на одном контексте и передавайте токены отмены в асинхронные методы.
- Не вводите универсальный репозиторий только ради размещения спецификаций; абстракция нужна лишь при реальной архитектурной границе.

## Проверка

Проверьте null, пустые результаты, приоритет AND/OR, ограничения доступа, границы страниц, проекции, отмену и SQL-трансляцию на настоящем провайдере. Для критичных запросов проверьте значительные объёмы и индексы. Зафиксируйте фактические версии EF Core/провайдера и запущенные тесты; документация не доказывает соответствие.
