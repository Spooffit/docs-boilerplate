# Доступ к данным с Dapper

**Применяется к:** .NET-проектам, намеренно выбравшим Dapper. Dapper — лёгкий объектный mapper; он не предоставляет полноценные миграции схемы или отслеживание объектов ORM.

## SQL и безопасный ввод

Параметризуйте пользовательские значения, не конкатенируйте строки напрямую в исполняемый SQL. При динамическом выборе таблицы, столбца или сортировки используйте строгий проверенный allowlist. Применяйте правильные параметры диалекта и явное сопоставление неоднозначных имён столбцов.

## Подключения, время жизни и транзакции

Явно определяйте владельца и срок жизни соединения, границы транзакций, отмену и тайм-ауты команд. Если API и провайдер поддерживают, используйте `CommandDefinition` для передачи токенов отмены.

Запрос внутри ambient или явной транзакции должен использовать правильное соединение и транзакцию. Если многошаговое изменение обещает атомарность, проверяйте откат при отказах.

## Качество запросов и проверка

Оценивайте производительность SQL на характерной нагрузке и задавайте явную пагинацию для больших наборов данных. Проверяйте параметры, отображение строк, null, транзакции и нарушения ограничений на реальном провайдере.

Не требуйте абстракцию repository вокруг каждого вызова Dapper автоматически. Выбирайте границы абстракций по ответственному компоненту и архитектуре проекта.

Источник: [репозиторий Dapper](https://github.com/DapperLib/Dapper).
