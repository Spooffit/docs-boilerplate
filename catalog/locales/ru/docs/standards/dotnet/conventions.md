# Соглашения для .NET и C#

**Применяется к .NET-проектам**, выбравшим этот профиль. Не считайте здесь описанные иллюстрации фактической архитектурой приложения.

## Код и структура

Соблюдайте существующие соглашения C# и правила редактора; используйте информативные имена, nullable reference types и явные границы ответственности. Асинхронные операции должны поддерживать корректную отмену; не блокируйте Task синхронным ожиданием.

## Ответственность при выбранной архитектуре

Если проект действительно использует слои, разделяйте domain/application/infrastructure и указывайте разрешённые зависимости. Не создавайте проекты, интерфейсы и абстракции ради шаблона. Выбранная библиотека или структура папок не подтверждает архитектурного решения.

## Доказательства

Указывайте реально выполненные dotnet build, dotnet test, анализаторы и источник конфигурации. Отдельно отмечайте примеры, которые не компилировались.

## Форматирование

Форматируйте изменённые исходники согласно принятому .editorconfig и фактическому SDK. Проверяйте итоговый diff и не включайте в задачу массовые посторонние изменения.


## Примеры кода

```sh
dotnet format --include path/to/changed-file.cs
```
