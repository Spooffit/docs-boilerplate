# Файлы проектов и зависимости .NET

## Назначение проекта

Поддерживайте явные зависимости и понятную ответственность каждого csproj. Не навязывайте фиксированное разбиение на слои, а также отдельные проекты Contracts, Domain или Infrastructure без действительной потребности.

## Зависимости

Добавляйте только реально используемые ProjectReference и PackageReference, соблюдайте ограничения архитектуры и версии совместимости. Центральное управление версиями, анализаторы, nullable и implicit usings должны соответствовать принятой конфигурации.

## XML-пример

Пример ниже иллюстрирует форму .NET-проекта; он не означает, что указанная структура уже существует.

## Формат и инструменты

Редактируйте csproj в UTF-8, избегайте скрытых неуправляемых зависимостей. После изменения собирайте и проверяйте именно затронутые проекты; не считайте успешное восстановление NuGet доказательством корректности функциональности.


## Примеры кода

```xml
<Project Sdk="Microsoft.NET.Sdk">
  <PropertyGroup>
    <TargetFramework>net10.0</TargetFramework>
    <Nullable>enable</Nullable>
  </PropertyGroup>

  <ItemGroup>
    <ProjectReference Include="../Contracts/Contracts.csproj" />
  </ItemGroup>
</Project>
```
