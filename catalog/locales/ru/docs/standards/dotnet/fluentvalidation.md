# Правила использования FluentValidation

**Применяется при выборе FluentValidation.** Не подменяет авторизацию или доменные инварианты и не требует отдельного слоя для каждой проверки.

## Владение правилами

Определите, какие ограничения являются синтаксическими, какие относятся к контракту операции, а какие требуют актуального доменного состояния. Выбирайте владельца правила и не дублируйте его с расхождениями в UI, DTO и доменной модели.

## Значения и нормализация

Разделяйте отсутствующее поле, null, пустую строку и значение по умолчанию; учитывайте unicode, пробелы, регистр и культуру. Для typed values нормализация и валидация должны сохранять семантику типа. Не принимайте чужую строку как корректный доменный объект лишь потому, что она прошла regex.

## Правила полей и вложенных объектов

Используйте атомарные правила, условия и вложенную композицию с явной областью применения. Проверяйте поведение RuleForEach, зависимых условий и каскадирования. Не скрывайте мутацию состояния в валидаторе.

## Этапы валидации

Входной запрос может требовать лёгкой проверки формата до авторизации; доменные правила проверяются перед фиксацией эффекта на доверенной границе. Асинхронные проверки доступа к БД или сервису нельзя автоматически считать согласованными с последующей записью.

## Async и ASP.NET Core

Проверяйте совместимость async validators с используемым ASP.NET Core pipeline и способом вызова. Не полагайтесь на неподдерживаемую синхронную автопроверку для асинхронного Rule.

## Ограничения и регулярные выражения

Размеры, диапазоны, enum и regex берите из реального контракта. Для regex задавайте разумные таймауты и избегайте опасного backtracking на недоверенном вводе. Не придумывайте лимиты и обязательность из шаблона.

## Проверка

Проверяйте каждый существенный положительный и отрицательный случай, null/empty, локализацию ошибок, вложенные правила, отмену, конкуренцию и реальную интеграцию ASP.NET Core. Помечайте проверки без фактического исполнения.
