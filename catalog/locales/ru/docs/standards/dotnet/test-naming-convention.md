# Опциональные имена методов тестирования .NET

**Опциональный профиль.** Не навязывайте его каждому .NET-проекту.

## Формат

Если команда приняла правило, используйте имена методов вида MethodUnderTest_Scenario_ExpectedBehavior. Название должно описывать проверяемое поведение, контекст и наблюдаемый результат; имена не заменяют ясных assertions.

Для параметризованных тестов называйте общее поведение, а данные передавайте средствами выбранного фреймворка. Не переносите методику именования в идентификаторы бизнес-сущностей.

## Применение

Применяйте правило последовательно только в выбранной области, не переименовывая существующие тесты без реальной пользы. Учитывайте особенности TUnit/xUnit и ограничения инструментов отчётности.


## Примеры кода

```csharp
public void Normalize_WhitespaceOnly_ReturnsEmptyString() { /* assertions */ }
public void Calculate_NegativeQuantity_RejectsInput() { /* assertions */ }
public async Task Submit_DuplicateRequest_DoesNotRepeatSideEffect() { /* assertions */ }
```
