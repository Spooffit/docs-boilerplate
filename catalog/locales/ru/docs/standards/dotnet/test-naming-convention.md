# Необязательное соглашение об именовании .NET-тестов

**Применяется, когда:** явно выбран профиль `test-naming-convention`. Базовый [стандарт тестирования .NET](testing.md) независим от фреймворка; выбор `dotnet`, TUnit или bUnit не включает это соглашение автоматически.

## Формат

Используйте `MethodUnderTest_Scenario_ExpectedBehavior` для имён тестовых методов с тремя содержательными частями через подчёркивание:

- **MethodUnderTest:** публичный метод, операция endpoint, правило или поведение. Для процесса из нескольких компонентов выбирайте устойчивую наблюдаемую операцию, а не приватный помощник или абстрактный `Execute`.
- **Scenario:** конкретный ввод, состояние или триггер, отличающий случай.
- **ExpectedBehavior:** внешне наблюдаемый результат, включая значимую ошибку или побочный эффект.

Иллюстративные сигнатуры, не зависящие от раннера:

```csharp
public void Normalize_WhitespaceOnly_ReturnsEmptyString() { /* assertions */ }
public void Calculate_NegativeQuantity_RejectsInput() { /* assertions */ }
public async Task Submit_DuplicateRequest_DoesNotRepeatSideEffect() { /* assertions */ }
```

Используйте написание, регистр и async-сигнатуру, поддерживаемые фреймворком. Сценарии называйте кратко, но различимо. Не кодируйте внутреннюю подготовку, случайные значения или имена классов только ради формата. Параметризованные тесты могут делить имя метода, если раннер однозначно показывает каждый случай и ошибочный ввод.

## Принятие и область действия

Это отдельно выбираемое **соглашение об именах**, а не обязанность использовать TUnit, xUnit, NUnit, конкретную структуру папок, слои или mocking library. Применяйте к новым и изменённым тестам согласно принятой политике; не переименовывайте массово ради соответствия без ревью. Другие проекты могут использовать другую схему, если этот профиль не выбран.

**Проверка:** можно анализировать наличие трёх осмысленных частей у принятых тестов; не путайте соответствие имени с качеством assertions или доказанным покрытием.
