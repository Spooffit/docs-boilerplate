# TUnit и Microsoft.Testing.Platform

**Применимость:** .NET-проекты, явно выбравшие TUnit.

TUnit — тестовый фреймворк .NET на базе Microsoft.Testing.Platform (MTP). API фреймворка и обнаружение тестов зависят от установленной версии. Не переносите автоматически аргументы CLI и расширения другого фреймворка.

## Конфигурация раннера

Для .NET 10 SDK и намеренного выбора MTP укажите в `global.json`:

```json
{
  "test": {
    "runner": "Microsoft.Testing.Platform"
  }
}
```

Проверьте, что версии TUnit и MTP поддерживают целевой SDK. Настройки раннера должны одинаково действовать локально, в фильтрах тестов и командах CI.

## Жизненный цикл тестов

- Используйте механизмы фикстур и жизненного цикла TUnit, поддерживаемые фактической версией пакета.
- Не делите изменяемое состояние между конкурентными тестами без явной изоляции.
- Избегайте зависимостей между тестами и утверждений, зависящих от порядка.
- Обеспечивайте детерминированную очистку ресурсов, включая ошибки подготовки.
- Публикуйте совместимые с MTP результаты через поддерживаемые расширения и аргументы CLI.

## Параллелизм тяжёлых наборов

TUnit допускает одновременный запуск тестов. Используйте его собственные средства, не создавайте отдельный планировщик только ради фикстур:

- `--maximum-parallel-tests` или `TUNIT_MAX_PARALLEL_TESTS` задаёт ограничение **на весь тестовый процесс**. Прежде чем копировать команду в CI, проверьте передачу аргументов реальным SDK и раннером.
- `[ParallelLimiter<T>]` с реализацией `IParallelLimit` ограничивает только тесты с общим бюджетом дорогих ресурсов.
- `[NotInParallel("resource-key")]` используйте при конфликте тестов за **один изменяемый ресурс**. Где возможно, предпочитайте изоляцию последовательному запуску.

Выводите конкретные пределы из измеренной ёмкости раннера. Лимиты отдельных проектов не ограничивают автоматически **суммарный** параллелизм независимых Integration, Functional и E2E заданий. Не тормозите Unit/Architecture лишь потому, что тяжёлым наборам нужен бюджет.

Источник: [TUnit: управление параллелизмом](https://tunit.dev/docs/execution/parallelism/).

## Существенные проверки совместимости

1. Подтвердите совместимость версий пакетов и целевых платформ.
2. Выполните локально точную команду `dotnet test` из CI.
3. Проверьте фильтрацию, отчёты и параметры покрытия на выбранной платформе.
4. Убедитесь, что процесс тестов завершается ненулевым кодом при ошибке теста.
5. При смене раннера сохраняйте небольшой заведомо падающий smoke-тест в тестах инструментов проекта.
