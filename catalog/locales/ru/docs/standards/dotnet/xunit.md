# Тестирование .NET с xUnit.net

**Применяется, когда:** проект явно выбирает xUnit.net для тестов .NET. Это альтернатива TUnit; для базового тестирования выбирайте только один фреймворк.

- Используйте `[Fact]` для тестов без параметров и `[Theory]` с атрибутами данных для параметризованных случаев.
- Делайте проверки детерминированными и ориентированными на наблюдаемый результат. Избегайте общих изменяемых фикстур, из-за которых тесты влияют друг на друга.
- Для асинхронного поведения используйте `async`-тесты, возвращающие `Task`, вместо блокирующих `.Result` и `.Wait()`.
- Явно задавайте жизненный цикл фикстур через конструктор, `IAsyncLifetime` или collection fixtures. Не предполагайте порядок запуска.
- Отделяйте модульные тесты от интеграционных, требующих реальных ресурсов. Testcontainers и Aspire testing остаются независимыми вспомогательными вариантами.
- Запускайте тесты с фактически установленными версиями SDK, раннера и пакетов xUnit. Не предполагается определённая основная версия xUnit или способ интеграции с раннером без доказательств.

Источники: [xUnit.net](https://xunit.net/), [.NET test](https://learn.microsoft.com/en-us/dotnet/core/tools/dotnet-test).
