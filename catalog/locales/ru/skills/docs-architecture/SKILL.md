# Архитектурная документация

1. Прочитайте `AGENTS.md`, `docs/project/overview.md`, `docs/architecture/overview.md` и относящиеся к задаче ADR. Изучайте только выбранные стандарты.
2. Отделяйте наблюдаемые компоненты и контракты от целевой архитектуры. Для реализации фиксируйте проверенный коммит, среду и тест; для проектного решения — источник согласования.
3. Описывайте реальные границы ответственности, доверия, владение данными, сбои и связи. Не навязывайте DDD, CQRS, микросервисы или новые хранилища.
4. При наличии значимых альтернатив оформляйте ADR, используя `docs/templates/adr.md`; не делайте из каждого технического параметра архитектурное решение.
5. Обновите затронутые ссылки и каталог документов. Сообщите неизвестное и противоречия, а не подменяйте их предположениями.
6. Проверьте структуру документации штатным `validate` при наличии генератора; эта проверка не доказывает поведение системы.
