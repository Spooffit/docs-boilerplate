# Repository baseline audit (2026-10-27)

## Scope and evidence

Baseline: `main` at `39cd3bed`. The repository contains 196 files (~5.8 MB). This document records a structural audit and targeted review of representative standards and templates; it is **not** a line-by-line technical certification of every legacy feature.

## Findings

| Priority | Finding | Evidence | Action |
| --- | --- | --- | --- |
| Critical | A project documentation repository is being reused as a template | `business/features/F01-...` through `F23-...`, `business/product.md`, module and question catalogs | Keep during extraction; exclude from generated repositories; remove only after full migration |
| High | Template versus generated-document boundaries are undefined | root `README.md` describes project documentation; `business/` and `technical/` mix deliverables with reusable material | Introduce `catalog/`, `src/`, `tests/` and a generated-repository contract |

| High | Testing standards split across S04 and S09-S15 | `technical/backend/standards/S04-testing.md`, `S09-architecture-tests.md` through `S15-test-engineering.md` | Keep classification by system under test; consolidate baseline rules; generate stack-specific guidance conditionally |
| Medium | Reference documents and navigation presume historical IDs | root catalogs `features.md`, `modules.md`, `questions.md`, `standards.md` | Generate relative links from the selected output plan, not fixed IDs |

| Medium | No generator, schema validator, or reproducible generation | no `src/`, `tests/` or profile catalog at baseline | Implement one generation engine, CLI, and output validation |
| Medium | Agent rules include historical product direction | root `AGENTS.md` references Demo scope and Q26 | Replace with short maintenance instructions referencing canonical docs |

## Material disposition

- **Extract/generalize:** `shared/templates/`, `business/templates/`, `technical/*/templates/`; the general principles in `S04`, `S09-S15`, `S02`, `S16`, `S23`, `S05`, and `S08`.
- **Preserve only as historical input while migration remains incomplete:** all `business/features`, `business/modules`, `business/questions`, `technical/*/features`, `technical/*/modules`, `technical/*/questions`, `milestones/`, root project-specific catalogs, and original product/architecture documents.
- **Replace with portable conventions:** README, CONTRIBUTING and AGENTS; clarify documentation ownership and generated-file lifecycle.
- **Avoid fake completeness:** no automatic migration of project-specific technical details into universal normative standards.

## Review decisions

1. Documents are the source of truth, not agent prompts.
2. A technology profile cannot claim support without real files, selection checks and tests.
3. Development practices tied to optional libraries stay opt-in.
4. Generated repositories contain no `src/`, `tests/` or `catalog/` internals.
5. Destructive cleanup is deferred until every affected document has been classified, generalized or explicitly rejected.
6. Generated files are not overwritten on re-run; previews and validation are read-only.
