# F13. Доставка и синхронизация контента: frontend / SDK contract

[Бизнесовая спецификация](../../../business/features/F13-content-delivery.md) · [Backend](../../backend/features/F13-content-delivery.md) · [M05](../modules/M05-delivery.md) · [F19 SDK](F19-unity-client.md) · [F20 сцена](F20-unity-demo-scene.md).

## 1. Результат и границы

Получатель выполняет один высокоуровневый вызов SDK и получает согласованный рабочий набор, результат применения, прогресс и отдельный результат актуальности. F13 описывает потребление Delivery runtime API через `Sdk.Client.DotNet` и адаптер `Sdk.Client.Unity`. Это не обязательная административная Blazor-страница доставки. Авторский UI создаёт и публикует данные через F02–F05; его CRUD не становится runtime API.

Demo синхронизирует Published ContentModeling по полному обязательному выбору точных `SchemaId + SchemaVersionId`. SDK передаёт фактический полный installed inventory, получает неизменяемый точный план и применяет данные, удаления и inventory атомарно для каждой пары. Несколько SchemaVersion одной Schema и несколько представлений одного EntityInstance допустимы. Сервер выбирает `latestPublishedVersionNumber` после фильтра точной SchemaVersion; SDK не вычисляет latest самостоятельно.

MVP получает одну целую entitlement-selected PublicationRevision через pinned DeliverySession. Demo synchronizationId и MVP SessionId/session credential имеют разные смысл и жизненный цикл. Атомарность одной структуры Demo не разрешает поэлементно смешивать лицензионные ревизии MVP. В Demo отсутствуют Identity, лицензии, broker, полное продуктовое Publishing и protected session.

Новая MVP admission использует confirmed SourceCurrentPeriod каждой подтверждённой лицензии и exact PolicyAgreement, сохранённый Publishing до VRS confirmation. Agreement не создаёт коммерческое право, first use не выбирает current policy. После renewal новый current period под Deny не получает fallback к старому same-license Freeze. Unity/SDK не вызывает Agreement issuance: это authenticated VRS backend workflow; приложение только получает typed entitlement/readiness результат CM.

Runtime использует отдельную ASP.NET scheme `CmDeliverySession`: staff identity не заменяет session credential, Demo остаётся anonymous. Raw activation keys поступают от application credential provider только для нового admission либо creation replay, не ordinary manifest/item/asset reads. SDK не сохраняет raw key или его hash по умолчанию. Session credential opaque, передаётся CM по HTTPS Authorization header, не URL/log/S3 forwarding. Server 32-byte CSPRNG/base64url token, SHA-256 verifier и short encrypted Data Protection replay capsule определены в backend F13; capsule — явное краткосрочное исключение hash-only хранения, не client key storage.

Delivery committed effective snapshot и availability-history confirmation различны. Conservative stored VisibilityConfirmedAt появляется один раз после primary observation exact уже committed полного transition; это не physical commit/precommit/Publishing time. Current snapshot/предыдущий допустимый effective состав могут обслуживаться при разрешающих фактах во время catch-up или confirmation Pending. Для Freeze necessary incomplete history/confirmation даёт Indeterminate: no earlier-nonnull fallback. UI/SDK не называют history ready по одному совпадению RevisionId. Модели и поля принадлежат [backend F13](../../backend/features/F13-content-delivery.md); runtime/admin metadata carrier — Q15.

Доставка assets самостоятельна: приложение получает bytes по AssetId через CM-owned `/storage/assets/{assetId}` → CM host / YARP → private MinIO. Upload, metadata и lifecycle принадлежат CM API [F05](F05-media-assets.md); runtime не получает endpoint/bucket/ObjectKey/storage credentials или обязательный presigned S3 URL. Read gateway допускает GET/HEAD, не upload/delete. Public route, SHA-256 validator/cache/Range semantics закреплены [Q21](../../backend/questions/Q21-media-storage.md#yarp-metadata-lookup-и-access-boundary); low-level provider integration проверяется при реализации. Это целевой contract, не утверждение о готовом runtime route.

На 09.10.2026 Demo routes/DTO/streaming реализованы в Delivery.Api и owning Application/Persistence adapters; [backend F13](../../backend/features/F13-content-delivery.md) описывает implementation и серверные verification boundaries. В административном Blazor UI отдельный F13 экран не требуется. Generated `ISynchronizationClient` / `SynchronizationClient` обновлены из фактического OpenAPI временного Windows API под Spooffit только через `.run/generate-api-client.run.xml` / `.tools/generate-api-client.sh`. Start, Status, Resume, Stop, Discard, Commit и Freshness используют typed DTO; `DataAsync` требует `planId` и возвращает raw `FileResponse.Stream` с `ResponseHeadersRead`, сохранёнными headers и владением response до `Dispose`. Generated source вручную не изменён; старого catalog `SynchronizationAsync` в нём нет.

Полный UI build и runner F01–F05/F13 прошли после последней генерации. `F13TransportTests` через generated клиент и штатный envelope handler проверяет exact HTTP paths/DTO, escaping cursor, отсутствие implicit NDJSON buffering, independent Commit при ожидающем stream, terminal/EOF, ownership/disposal и typed `application/problem+json` ошибки. Подтверждённая регрессия MIME устранена: handler разбирает только `application/json` и `application/*+json`, а `application/x-ndjson` передаёт как raw stream. Это client/HTTP-fixture verification; UI server не запускался. SDK orchestration/durable store принадлежат F19, сцена — F20; серверные tests и codegen не подтверждают их готовность. Protected `InternalDeliveryService` сохраняет прежний trusted контракт и не доказывает целевой MVP admission/session credential.

FSD используется как карта ответственности шаблона, а не требование построить Unity-пакеты по каталогам Blazor/TypeScript. `app/pages` здесь принадлежат приложению-получателю; `features` соответствует высокоуровневому поведению DotNet; `entities` — runtime-представлениям; `shared` — техническим портам. Это логические обозначения, не существующие имена классов. Отдельный widget F13 не нужен: основной состав SC01 уже описан F20.

## 4. Логическая компоновка

```text
SC01. Сцена F20 / SC02. Представление приложения
  Контекст: адрес CM, полный exact selection
  Координатор приложения
    Публичная операция F19
    Представление результата: execution, группы, свежесть, отдельная asset error
  Текущий committed набор
    Typed поля exact SchemaVersion + EntityInstanceKey
    Изображение из отдельно вызванного Assets API
```

SDK и transport являются зависимостями координатора, а не дочерними визуальными элементами. Приложение одновременно может показывать прежний рабочий набор и ход загрузки staging. Неполная группа не заменяет карточки; после её atomic commit обновляется весь соответствующий exact context. Другие завершённые группы могут уже отображаться.

| Связь частей | Сведения | Координатор | Результат |
| --- | --- | --- | --- |
| Контекст → F19 | Полный exact selection; state boundary даёт actual inventory | Приложение | SDK начинает или восстанавливает одну операцию |
| F19 → представление результата | Progress download отдельно от committed groups, ошибки/остановка, freshness | Приложение / F20 | Нет ложного «установлено» по числу скачанных байтов |
| Atomic commit → typed read → карточки | Подтверждённая exact группа и новый inventory | SDK, затем приложение | Отображается согласованный набор, включая removals |
| Assets API → изображение | AssetId и самостоятельный ресурс/ошибка | Приложение через F19/Unity helper | Ошибка картинки не откатывает sync данных |
| Post-success preflight → приложение | UpToDate/ChangesAvailable либо client Unknown | SDK | Приложение выбирает следующий sync; автоматического цикла нет |

### 4.1. Launcher readiness и pinned Player после Demo

Digital Space Launcher продолжает устанавливать builds из ProjectStorage; для CM синхронизирует структурированные entities/AssetReference и committed inventory через F19. Он получает отдельный resolved asset requirements manifest для той же разрешённой revision и exact поддерживаемых build SchemaVersions. Предложенный server-resolved manifest contract ещё Q37. Источник требований/mapping legacy Project/Application ↔ canonical Product/ProductVariant не определяется Name/latest; exact carrier — [Q37](../questions/Q37-launcher-asset-delivery.md). F13 Start/Data/Commit/Status wire v1, групповые receipts и freshness сохраняются; binary downloads/jobs не часть F13-потока.

SC03. Launcher content readiness относится к launcher Unity UI, не CM Blazor/FSD: build/Variant context → EntitiesReady → required-assets counter → bytes/verification progress → optional preload state → LaunchAllowed/typed failure. Показать X/Y обязательных ресурсов, скачано/всего bytes, дополнительное место, paused/disk-full/no-access/verifying. Exact ETA не обязателен. Buttons Pause/Resume/Retry и поведение при закрытом launcher ещё Q37; не назначать UX-политику из иллюстрации.

## 5. Зависимости и публичные границы

Направление: приложение → Unity facade при его использовании → `Sdk.Client.DotNet` → заменяемый HTTP transport и state adapter. DotNet не зависит от сцены, UnityEngine, административного Domain/EF или S3 SDK. Обычный .NET transport и Unity transport реализуют публичную техническую границу; optional Addressables находится в [F23](F23-unity-addressables.md) и не требуется для F13.

Высокоуровневые sync/stop/discard/progress/result, session operations и typed read являются логическими публичными контрактами F19, а не назначенными в этом документе C#-сигнатурами. Приложение принимает callbacks/results без обратной зависимости SDK от классов сцены. Изменение этих границ затрагивает F20 и другие .NET/Unity-потребители; точные namespaces, signatures и правила disposal — Q29.

CM определяет desired set и право доступа. Client selection, hash, EntityInstanceKey и synchronizationId не являются доказательством entitlement. Unity не обращается к VR School для самостоятельного объединения прав. Runtime contract не подменяется NSwag admin client; доступ к чужим ресурсам проверяет сервер.

| Файл/Unity resource | Отдельный Assets API и resource lifecycle | Приложение/Unity helper | Самостоятельная загрузка/освобождение; не часть data-group commit |

CM хранит immutable plan в bounded process memory одного host. Absolute TTL по умолчанию 1 час от atomic reservation, настраивается backend, не продлевается preparing/streaming/stopped requests/lease. Restart теряет plans: SDK создаёт новый от actual inventory. Mutable execution/generation/lease отдельно от target/records/hash/cursor. Data GET сам получает generation/lease; competing live lease даёт 409, expired owner может быть заменён с fencing позднего worker. Active plan не вытесняется произвольно ради capacity нового Start. Это не TTL клиентских installed данных; numeric settings/реальная реализация остаются Q33/Q29/Q32.

Exact SchemaVersionId задаёт minimum atomic group, SchemaId её context. Start содержит только изменённые группы в canonical schemaId/schemaVersionId порядке; deselected группа имеет пустой target. No-change возвращает groups:[], Data — только operationCompleted, zero receipts. [Public wire v1](../../backend/questions/Q33-sync-resume-transport.md#public-wire-contract-v1) использует camelCase protocolVersion=1, normal recordSequence 1..N immutable plan и последовательные группы без interleave. Server models/payloads принадлежат [backend F13](../../backend/features/F13-content-delivery.md#33-dto-и-parameter-models), здесь описано их использование.

entityUpsert.payload.contentJson — JSON **string** с exact original canonical JSON. SDK снимает JSON escaping → строго восстанавливает исходные UTF-8 bytes без изменения текста → проверяет supported profile+SHA-256 digest → typed parse по exact binding. LF framing/внешнее escaping не входят в content digest; parse→reserialize, double conversion Long/Decimal и automatic rehash запрещены. По [Q19 v1](../../backend/questions/Q19-content-hashes.md#принятый-canonical-profile-v1) digest — 64 lowercase hex без prefix; unknown profile/corruption blocks apply. Neutral canonical models/library once backend F03, no runtime Registry fetch/profile picker.

Cursor normal record — checkpoint candidate: full validated record+cursor сохраняются атомарно в durable staging; parsed/network-only bytes не продвигают позицию. SDK считает cursor opaque, server проверяет HMAC/binding synchronizationId+planId+afterSequence; cursor не authorization/install proof и не HTTP byte range/SSE event ID. Resume сохраняет original sequences; identical identity/full parsed payload/restored content bytes dedup, mismatch той же sequence — protocol error. Mid-group resume требует сохранённых header/metadata/staging. groupCompleted сверяет plan/groupStarted, actual Add/Update/Remove counts, baseGroupHash/profile с исходной local group и **весь target после upserts/removals**, включая unchanged members, exact versions/Key/profile+digest и targetGroupHash/profile. Counts одни не доказывают target. Atomic data/removals/index/inventory/local receipt commit активирует полную группу; old group remains до commit, partial success допустим между целыми группами.

После local commit SDK сообщает receipt body planId/targetGroupHash/targetGroupHashProfile, schemaVersionId берётся из route. Same evidence возвращает same ACK acknowledged:true, другое — 409; server ждёт receipt перед next group. Lost ACK сверяется по durable local receipt/Status и повторяется без local reapply. Status разделяет planState и executionState, возвращает accepted receipts; completed означает все server receipts, не installed proof. Full success требует valid operationCompleted, всех local commits/ACKs и корректного HTTP response end. operationInvalidated — terminal recordSequence=0/no cursor вне planned sequence: unfinished останавливается, committed сохраняется; invalidation/truncation не success. cm-installed-inventory/1 описывает actual installed, не selections/staging; cm-sync-plan/1 original request fingerprint+pinned targets/groups/removals исключает random ID/time/progress/receipts и не меняется от own commit. Immutable canonical bytes/profile/digest preserved, no historical rehash.

SDK захватывает executionGeneration из Status и `X-CM-Sync-Execution-Generation` из Data headers; NDJSON/cursor generation не получают. Control использует planId/captured expectedExecutionGeneration; Resume также original fingerprint/profile. Stale command409 не перенаправляется автоматически на fresh generation. Lost control ACK выясняется identical repeat original command → original result snapshot и отдельным Status; это не fresh state и не основание local reapply. Поля/control DTO определены один раз backend F13; orchestration/state ownership раскрыты [F19](F19-unity-client.md#72-resume-новый-запуск-stop-и-discard).

Для UI01 отсутствующий/невалидный selection не подменяется пустым. Явный empty selection вместе с полным actual inventory означает planned managed removals. Отказ от одной пары удаляет только её управляемые representations. Withdrawal whole Schema, exact SchemaVersion или logical EntityInstance влияет на серверный desired set; SDK исполняет exact removals, не угадывает причину.

Для UI02 новый ID допустим при доказанном отсутствии/expiry/discard/invalidation старого plan либо explicit new selection intent; actual installed inventory авторитетен, прежний ID не получает новый состав. Staging reuse только после exact identity/content проверки. Timeout/409/unknown outcome не доказывают невозможность resume. Gate стабильного store scope действует между SDK instances и отклоняет второй high-level вызов до генерации ID, без отмены первой/default очереди/join; local run generation отсекает поздние parser/callback/control outcomes. Cross-process locking/recovery выбранного adapter требует proof Q29/Q32.

PlanId доступен в Status уже при preparing без ready plan metadata. Resume с original request fingerprint/profile может закончить первую подготовку после Stop; готовый immutable target не переписывается. Resume проверяет identity/eligibility и разрешает stopped/idle, но не открывает/резервирует stream: следующий Data GET получает собственную lease/generation. Старое control намерение не retarget-ится на нового worker. Retained completed plan и durable terminal при unknown HTTP end позволяют replay/dedup terminal suffix. Recovery не переписывает original fingerprint своими commits.

Если exact payload старого плана запрещён из-за withdrawal, группа признаётся invalidated, прежняя рабочая группа сохраняется; восстановление требует нового plan, а не подстановки latest в старый. В новом плане авторитетно подтверждённый withdrawal/допустимое Demo-удаление scope порождает соответствующие Remove. Неизвестная/непрочитанная SchemaVersion без такого подтверждения является group error, не пустым desired set. Failed source response не разрешает удаления; negative-state evidence остаётся backend Q20/Q33. Неизвестный сетевой исход commit/status не равен доказанному отказу: SDK выясняет результат и соблюдает idempotency backend contract.

Для UI07 клиент общается только с CM. Raw activation key от app provider передаётся только admission/creation replay; CM readonly authoritative VRS validation не является grant. Stale cached proof не создаёт новую session при outage; valid key с missing required CM facts не InvalidKey. HTTP outcome meanings выбраны в Q16, exact JSON/read/request/replay carrier — Q15.

CreationRequestId сохраняется до POST вместе с requested Variant и nonsecret credential selection context; verified CredentialId/LicenseId logical identity формируется сервером после readonly VRS CMContent validation, не из client assertion. Receipt не хранит raw key/hash либо volatile proof epochs/source versions/times как input identity. Lost response повторяет тот же ID/logical input с keys от app provider и fresh source validation; existing receipt replay проверяет **original pinned eligibility**, а не выбирает новую current candidate. Token/result original, TTL не extended, revoked/expired/invalidated session не restored. Temporary DB/keyring/unknown outcome сохраняет same ID retry. Proven ReplayExpired/irrecoverable capsule loss завершает secret replay: новое осознанное admission/new ID не закрывает остальные sessions и не вводит one-session-per-license rule; metadata receipt retention — engineering detail.

Server configurable defaults: absolute session TTL 30 min, secret replay window 5 min не дольше session expiry, proof age 30 s, response lease 5 s. Это server settings, не client таймеры/формы или physical network SLA. Session expiry=min(absolute TTL, finite agreed Deny cutoff, explicit credential deadline), **не** application ExpiresAt; sliding/refresh endpoint отсутствует. Source ValidatedAt audit-only: proof age измеряется CM monotonic от начала VRS HTTP до final gated check, включая transport/crypto/wait. Expired proof повторно проверяется вне gate. Source credential security epoch и license watermark независимы; current required CM facts не ниже hints/ready. Точные carriers/security-state models — backend F13/Q23.

Missing Agreement, unavailable current-period marker/cutoff/required facts дают Indeterminate/DataNotReady; complete authoritative no-grant и explicit grant/license revoke дают разные Denied reasons. Source planned/pending не confirmed entitlement. Приложение показывает причину ожидания и может повторить safe read/session попытку по контракту, но не выдаёт Agreement, не вызывает commercial confirm и не «лечит» ожидание новым policy/default. CM content grant может ожидать CM Agreement readiness при уже существующей application license; Project Storage/download/launch flow независим.

Полный caller-verified set рассматривается строго: если для любого нужного лицензионного основания данные Unknown, итог Indeterminate, без partial known-Allowed selection. Determinate Denied+Allowed допускает одну most-current whole Allowed revision, без item merge. Один предъявленный key подтверждает только свою лицензию; single-license selection допустим явно. Пересчитывать policy/Freeze, выбирать SourceCurrentPeriod либо добавлять лицензии организации в browser/Unity запрещено. Backend F12 владеет моделями и выбором; exposed reason/provenance carrier — Q15.

При одинаковой most-current whole candidate tie выбирается min LicenseId, затем min credential identity. Session закрепляет только selected license/credential/period/Agreement/revision. Unselected revoke не отменяет session; selected revoke не переключает её на другое известное право и не делает auto fallback. Каждое ключевое основание full creation set проверяется fresh; отсутствие needed proof/facts блокирует whole admission.

Required history/confirmation Pending также относится к needed Unknown. Freeze учитывает stored VisibilityConfirmedAt строго меньше current UpdatesUntil: late/equal excluded, complete null no older-nonnull fallback. Late ordinary Unpublish не отменяет prior Freeze. Rollback новый transition/time. Whole candidate order effective transition, не artifact age; same-candidate tie min LicenseId/credentialId server-side. Correction даты пересчитывает cutoff по прежним Agreement/confirmation history, не policy и не TTL.

Ordered source catch-up/gap recovery не подставляет latest в outcome: terminal intermediate NotEffective без availability row, technical missing artifact не consumed success. Confirmation replay original stored time, recovery без saved result fresh/no backdate. Independent exact ban survives inactive/unmaterialized/late replay. Admission/checkpoint проверяет owner authority перед cache/304/Range; required unknown не cached permission. Q17 visibility не authorization lease: TTL/transfer/known-invalidation timing выбирает approved Q16 response-deadline protocol, без physical-network SLA.

Для UI08 during active updates R1 pin остаётся допустимым несмотря на R2/new activation/ordinary Unpublish/Archive/Retire при сохраняющихся rights/hard restrictions. Ordinary VRS outage alone после creation не revoke и не требует HTTP validation на каждый read; current CM facts всё равно проверяются. Deny cutoff не обходится TTL. At expired Freeze/corrected cutoff pin должен совпасть с currently eligible whole frozen candidate: иной known candidate → NeedsNewAdmission/Invalidated, не repin; necessary unknown history → temporary DataNotReady, не revoke. New CurrentPeriod renewal делает старую period-session непригодной, требуется новое admission. Reasoned correction сохраняет Agreement/pin, но re-evaluates facts; known ineligible invalidates, unknown временно blocks. Cutoff expansion не extends TTL/не restores old session.

Known key/license/Variant-grant/exact-revision hard restrictions scoped к selected basis; restoration требует new session. Server checkpoint — короткая own guarded transaction с fresh own/public primary facts перед cache/304/Range/headers, затем bytes I/O вне gate. Response lease ограничена min(5 s default, session expiry, NEXT finite policy boundary включая Freeze cutoff). Periodic primary rechecks и **independent monotonic deadline** прекращают response при known invalidation/failure/deadline, даже если renewal ждёт gate; late callback не возрождает lease. Может требоваться новый HTTP request после policy boundary при still-valid session. Локальное after-commit cancellation — только optimization для одной replica. Source-to-CM propagation delay отдельно; это не 0 ms/5 s physical-network гарантия, buffers/already-sent bytes не отзываются.

Каждый Range/resume проходит fresh authorization checkpoint; token не forwarded в S3. После headers failure/abort не получает JSON в body: SDK считает outcome Unknown до typed response, не угадывает revoke по EOF и не resend-ит plaintext key на ordinary read. Proven new session создаёт новый session-bound plan; old plan/cursor не rebind silently. Уже installed данные сохраняются.

Success control responses используют существующий общий `ApiResponse<T>`; Data — raw application/x-ndjson UTF-8/no BOM, compact JSON + LF, parser LF/CRLF. CamelCase protocolVersion=1, kind/payload/cursor/recordSequence и шесть variants описаны backend F13; unknown version/kind, missing/duplicate required property, empty/malformed record/truncated tail — protocol error. Mutable authoring ETag/If-Match не переносится на immutable plan.

Execution/control profile добавляет POST `/api/v1/content-synchronizations/{synchronizationId}/resume`, `/stop`, `/discard` и POST `/api/v1/content-synchronizations/freshness`. Server models/field tables остаются backend F13. HTTP400 — malformed input/cursor; 409 — active ownership/stale control/plan/receipt mismatch; 404 — unknown ID/restart loss. HTTP410 — known expired/discarded только до bounded tombstone eviction; затем 404. Outage/timeout Unknown, не Missing/Expired. До headers normal error; после operationInvalidated/truncated stream без JSON envelope в NDJSON. Retained completed plan допускает terminal replay. Public wire/execution/control/Freshness согласованы Q33; SDK public/store contract выбран F19/Q29; numeric config/literal error mapping и actual adapter/transport/race checks остаются Q29/Q32. Machine reason/error mapping/concrete server integration — Q15/F13.

Data выдаётся одним обычным конечным streaming HTTP response последовательно по exact SchemaVersion groups; interleave групп не принят. Отдельного SSE control/progress/notification channel, chunk GET API и двух SSE streams нет. Клиент читает records инкрементально без буферизации всего payload; сервер не пересчитывает latest во время чтения. HTTP/3 предпочтителен при реальной поддержке среды, HTTP/2 fallback обязателен с прежним synchronizationId, immutable plan и durable checkpoint. HTTP/1.1 не согласован. Ошибка сертификата/контракта или предметный отказ не является основанием для protocol fallback. Реальный negotiated protocol и Unity transport capability ещё не проверены.

Unary/header/read-idle/record-assembly/storage-validation-commit/receipt budgets разделены; HttpClient ResponseHeadersRead timeout ограничивает только ожидание headers, body ограничивается отдельно. Read-idle приостанавливается во время ожидаемых local validation/atomic commit/receipt POST, соответствующий stage deadline и server watchdog продолжают действовать. Нет heartbeat/empty lines NDJSON; первая Demo HTTP compression выключена, её включение требует actual incremental проверки. Bounded transient retries используют backoff/jitter только в safe boundary; corruption/validation/lifecycle/confirmed invalidation не auto-retry, 409/timeout не new-ID fallback. Numeric defaults/buffers/limits и реальная Unity/proxy проверка остаются Q29/Q32/Q33.

MVP ordinary requests используют SessionId + selected opaque `Authorization: Bearer` credential по runtime-only CmDeliverySession, без raw key/staff token. Server verifier SHA-256/32-byte CSPRNG base64url и short encrypted replay exception выбраны [Q16](../../backend/questions/Q16-activation-and-sessions.md#принятый-протокол-сессий-и-response-leases). Hash match не заменяет fresh checkpoint/membership. Before YARP/cache/304/Range права подтверждает response lease; every Range/resume новый checkpoint, CM token не S3 authority. Exact response/receipt/error models — Q15, SDK не копирует server DTO. Текущий GetAssetAsync presigned URL остаётся разрывом с CM-owned YARP. Non-JSON gateway errors не successful bytes; postheaders truncation Unknown, не typed revoke.

Content-Type и Content-Length сохраняются, когда их возвращает provider. Storage ETag/cache validator не является mutable metadata ETag/internal Version и не автоматически SHA-256. Range/206/416 и conditional/cache semantics требуют actual gateway/provider/Unity integration tests Q21/Q29; только header forwarding не подтверждает их. Optional OutputCache и примеры 1 час/128 MB/10 MB не выбирают runtime cache policy, а cache body limit не ограничивает скачивание большого файла. Archive сохраняет historical bytes, но право чтения устанавливает CM context. Resource lifetime/cancellation остаются F19/Q29: gateway request/EOF не являются durable sync checkpoint, group receipt или atomic local commit data.

Для административного web UI применяется [S06](../standards/S06-api-client.md) и NSwag, но F13 runtime не требует его использования вместо F19. Generated admin client не редактируется; существующая catalog synchronization unrelated. Точные data models получаются F21/F22 до runtime; Domain/EF в клиент не импортируются.

Область ошибки — операция либо группа, а не обязательная блокировка всего приложения. DotNet не рисует окна и не навязывает UI для автоматического resume. SC01/SC02 показывают понятные подписи действий и ошибки; основные действия доступны в применимой клиентской среде. Controls/focus SC01 определены F20/Q26; SC02 остаётся обязанностью приложения. Для web-представлений применимы [S05](../standards/S05-ui-and-forms.md) и [S07](../standards/S07-accessibility.md). UI-блокировка второго запуска улучшает UX, но DotNet проверяет конкуренцию независимо от неё.
