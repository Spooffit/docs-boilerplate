# S12. Functional tests

## Область применения

Проверка конкретной функции одного deployable application. SUT: один deployable unit, например ASP.NET Core API, с необходимыми ему техническими зависимостями.

Главный вопрос: **выполняет ли приложение заявленную функцию через свой публичный интерфейс?**

## Вход в SUT

Основное действие выполняется через HTTP, gRPC либо другой реальный внешний интерфейс приложения. Прямой вызов внутреннего handler вместо внешней операции не подтверждает весь этот путь.

Предпочтительная структура:

```text
Arrange external state
Act through public interface
Assert observable result
```

## Запуск одного приложения

Для ASP.NET Core используется прежде всего WebApplicationFactory, если архитектура позволяет такой запуск. Реальные инфраструктурные зависимости предоставляются через Testcontainers.

```text
Test → HTTP → WebApplicationFactory → Application
                                      ├─ PostgreSQL
                                      └─ RabbitMQ
                                         ↑
                                    Testcontainers
```

WebApplicationFactory запускает SUT, Testcontainers предоставляет инфраструктуру. Они не заменяют друг друга. Тест не расширяется до всего distributed application без необходимости.

## Assertions

Предпочтителен результат, наблюдаемый через внешний интерфейс. Не следует без необходимости проверять конкретный handler, repository, внутренний service, число его вызовов или internal method.

Gray-box проверка БД или другой инфраструктуры допускается, если результат невозможно или неразумно проверить публичным способом. Это исключение, а не основной стиль Functional tests.

## Данные и асинхронная обработка

Тест готовит свои исходные данные. Его БД и broker namespace не пересекаются с Integration и E2E. Асинхронный результат ожидается по наблюдаемому условию с timeout и cancellation, а не фиксированным Task.Delay.

## Проверка соблюдения

SUT остаётся одним приложением. Основное воздействие проходит через публичный интерфейс. Реальные зависимости подготовлены автоматически, а проверка результата не привязана к случайному внутреннему устройству.
