# S09. Архитектурные тесты

## Область применения

Автоматическая проверка формализованных архитектурных ограничений кода, сборок и project references. Проверяются правила выбранного архитектурного стиля, а не работа приложения с БД или брокером.

## SUT и граница

SUT: структура приложения и её зависимости. Architecture tests не требуют Docker, внешней инфраструктуры и предварительного выполнения других тестов.

Точное перечисление сборок, пространств имён и запрещённых связей конкретного приложения определяется вне общего стандарта. Тест не должен закреплять старую архитектуру только потому, что ограничение существовало раньше.

## Проверяемые ограничения

Для архитектуры с соответствующими слоями и границами проверяются:

- направление зависимостей Domain / Application / Infrastructure / Presentation и отсутствие запрещённых зависимостей;
- границы Bounded Context и отсутствие прямого обращения к внутренним реализациям другого контекста;
- отсутствие циклических project references;
- размещение Domain entities, value objects, application handlers и infrastructure implementations по установленным правилам;
- направление зависимостей между abstractions и implementations;
- зависимости общих BuildingBlocks и отсутствие в них бизнес-логики конкретного контекста;
- зависимости фокусирующих и рассеивающих сборок, если такая модель сборок явно используется.

Дополнительные ограничения включаются, когда они формализованы. Этот перечень не является требованием создать отсутствующие в системе слои или виды сборок.

## Работа с существующим механизмом

Сначала оцениваются существующие архитектурные тесты и используемый механизм проверки. Достаточный API переиспользуется. При необходимости механизм адаптируется или расширяется; переносимый локальный boilerplate остаётся техническим и не содержит правил отдельного домена.

Старые тесты используются как источник понимания ограничений и полезных проверок, но не копируются механически. Устаревшие предположения проверяются относительно принятой архитектуры.

Правила конкретных сборок располагаются рядом с их архитектурными тестами. Общая библиотека содержит механизм проверки, а не список особенностей одного приложения.

## Проверка соблюдения

Тесты запускаются отдельно без Docker. Для каждого архитектурного ограничения понятно, какая структура проверяется и какое нарушение обнаруживается. Наличие библиотеки архитектурных тестов без самих проверяемых правил не считается покрытием архитектуры.
