# Q31. Контракты Schema Registry и генерации C#


## Принято

Дополнение [Q37](../../frontend/questions/Q37-launcher-asset-delivery.md) требует versioned formal annotation DeliveryMode на AssetReference definition, включая recursive ItemDefinition. Annotation name/codec/profile и совмещение с MVP constraints+Offset **уточняются**. Frozen cm-json-schema/1/cm-csharp/1 и исторические generated bytes не меняются молча. Generated runtime AssetReference сохраняет пять agreed полей; mode не становится свойством значения экземпляра. Launcher requirements поступают из отдельного resolved manifest, не current/latest Registry fetch.

[Q19](Q19-content-hashes.md#принятый-canonical-profile-v1) закрывает source canonical profiles/SHA-256/string/numeric/member ordering. cm-schema-content/1 source semantic digest/profile и cm-json-schema/1 exact representation ETag независимы; cm-csharp/1 остаётся своим generation contract. Registry annotations не входят в semantic hash, codegen получает formal exact contract и supplies уже известную typed metadata для SDK без runtime Registry fetch. Это не новый UI profile selector и не silent byte-changing upgrade tooling profile; literal export/source/library compatibility проверяется отдельно.


Schema Registry и C# generation используют одну формальную цепочку. Ниже показан frozen Demo `/1`; первый новый MVP bundle совместно включает Q35 constraints и согласованный Q34 Offset с новыми совместимыми profiles без смены истории:


```text
Published EntitySchemaVersion
        ↓
F21 Schema Registry exporter
        ↓
JSON Schema Draft 2020-12 + cm-json-schema/1
        ↓
Schema.CodeGeneration.Core
        ↓
cm-csharp/1
        ↓
deterministic .g.cs
        ↓
complete deterministic ZIP
```


F21 остаётся language-neutral формальным контрактом точной Published SchemaVersion. F22 C# generation является одним consumer этого контракта. Generator не строит типы по экземплярам, не читает Domain/EF models через reflection и не делает HTTP loopback к собственному Registry.


Demo UI выбирает exact `SchemaVersionId` и получает ZIP с `.g.cs`. CLI, source generator, Unity Editor/build/CI integration и manifest-driven workflow относятся к MVP/tooling и не являются условием Demo.


## 1. JSON Schema profile F21


### 1.1. Dialect и profile identity


Используется только JSON Schema **Draft 2020-12**:


```json
{
  "$schema": "https://json-schema.org/draft/2020-12/schema"
}
```


Несколько dialect одновременно в Demo не поддерживаются.


CM-specific semantics versioned отдельно от JSON Schema draft. Profile v1 имеет identity:


```text
urn:vrschool:content-manager:json-schema-profile:1
```


Документ содержит extension `x-cm-profile` с этой identity. Значение существующего profile не меняется несовместимо: новый смысл требует нового profile version.

MVP typed constraints и List comparer согласованы [Q35](../../../business/questions/Q35-value-constraints.md); Offset DateTime — [Q34](../../../business/questions/Q34-schema-field-semantics.md#datetime-mvp-temporal-semantics-и-совместимость). Первый новый MVP profile set совместно включает оба решения: новые `cm-schema-content`, `cm-instance-content`, `cm-json-schema` и `cm-csharp` profiles. Q35 constraints сами по себе не меняют runtime encoding; Offset runtime bytes меняются, поэтому instance `/1` недостаточен для Offset. Old `/1` остаётся frozen baseline с прежними exact bytes/hash; история не rehash-ится и не переэкспортируется под новым смыслом. Group/inventory/manifest profiles меняются только при собственном layout/semantics change и используют existing content-profile identifiers. Exact whole new-profile codec/identities/byte layouts/extensions/golden fixtures ещё **Уточняется** Q19/Q31; product temporal choice закрыт, готовый `/2` codec не объявлен.


### 1.2. `$id` и exact version identity


Registry identity не зависит от deployment hostname, текущего Schema key либо API route.


Exact Published SchemaVersion получает:


```text
$id = urn:vrschool:content-manager:schema-version:{SchemaVersionId:D}
```


GUID в machine-readable Registry representation сериализуется lowercase в canonical `D` format.


`SchemaId`, `SchemaVersionId`, положительный Published `VersionNumber`, frozen `PublishedSchemaName` и frozen `PublishedSchemaKey` берутся из immutable Published snapshot. Rename logical EntitySchema не переписывает старые Registry documents.


### 1.3. Dependency model


Demo SchemaVersion document self-contained. ContentModeling сейчас не имеет field-definition ссылки на другую EntitySchema, поэтому cross-schema `$ref` graph не вводится.


Внутренний `$defs` разрешён exporter-у для детерминированной структуры документа, но не создаёт external dependency closure. `Object` и recursive `List` описываются внутри exact SchemaVersion contract.


### 1.4. CM extensions и annotations


Стандартные JSON Schema annotations используются там, где они соответствуют смыслу:


- `title` — authoring label;
- `description` — authoring help/description;
- `deprecated` — deprecated field/option metadata там, где применимо.


CM-specific semantics выражаются `x-cm-*` extensions. Profile v1 включает необходимые сведения:


- `x-cm-profile`;
- `x-cm-schema-id`;
- `x-cm-schema-version-id`;
- `x-cm-version-number`;
- `x-cm-field-id`;
- `x-cm-field-data-type`;
- `x-cm-order-mode` для List;
- `x-cm-asset-kind` для AssetReference;
- option metadata, необходимую для stable key/deprecated semantics.


`Name` и `HelpText` не определяют runtime property identity. Runtime property identity строится по immutable field `Key`, а stable historical identity сохраняется через `SchemaFieldId` extension.


### 1.5. Presence, null и additional properties


Profile v1 различает отсутствие property и `null`.


- optional field может отсутствовать;
- `null` не является допустимым значением ни для одного из текущих 15 типов;
- required задаётся стандартным JSON Schema `required`;
- schema-level `default` в Demo не экспортируется;
- Object запрещает неизвестные named properties через `additionalProperties: false`.


Required означает presence + type-validity. `0`, `false`, zero/negative TimeSpan, empty FlagEnum/List и `#00000000` не считаются отсутствием.


## 2. Formal mapping всех FieldDataType


### 2.1. String и Text


`String`:


- JSON type `string`;
- `minLength: 1`;
- `maxLength: 255`.


`Text`:


- JSON type `string`;
- `minLength: 1`;
- restricted sanitized HTML ContentModeling: paragraphs/br/lists/bold/italic; semantic empty проверяется после очистки, не одной minLength. Max — explicit server configuration, число выбирается representative Text fixture и показывается UI; Registry не назначает собственный случайный cap.


Text остаётся CLR string. Санитизация выполняется до Save/Publish в ContentModeling, exporter/codegen не переписывает Published текст.

Числовой cap — operational Save/Publish policy, не mutable input exact historical Registry export. Exporter не читает сегодняшний cap, чтобы поменять bytes уже Published contract; formal profile/annotations фиксируются snapshot/profile. Применение новых limits не переписывает исторические values.


### 2.2. Integer, Float, Decimal


C# profile v1:


| CM type | JSON Schema | C# |
| --- | --- | --- |
| Integer | `integer` | `long` |
| Float | `number` | `double` |
| Decimal | `number` + `x-cm-field-data-type=Decimal` | `decimal` |


Float принимает только finite values. Decimal не сводится к double. JSON Schema `number` сам не различает Decimal/Float, поэтому CM semantic extension обязательна.


### 2.3. Boolean


`Boolean` → JSON `boolean` → C# `bool`.


`false` является корректным present value.


### 2.4. Date


`Date`:


- JSON string;
- `format: date`;
- canonical wire `yyyy-MM-dd`;
- C# profile использует `global::ContentManager.Sdk.Client.DotNet.LocalDate`, readonly date-only value type для `netstandard2.1`; converter не добавляет timezone.


### 2.5. DateTime: exact Naive и Offset semantics


Demo `DateTime` имеет naive/local-contract semantics без timezone/offset.


Он **не** маркируется стандартным JSON Schema `date-time`, потому что это создало бы ложную RFC3339/offset semantics.


Profile использует CM format annotation/extension. Canonical JSON string — `yyyy-MM-dd'T'HH:mm:ss.fffffff`, всегда 7 fractional digits, без Z/offset, например `2026-10-05T14:30:00.0000000`. C# DateTime Kind=Unspecified; converter сохраняет precision без implicit UTC/local conversion. UI display с меньшей точностью не теряет сохранённые ticks.


`DateTimeValueDefinition.TemporalSemantics` immutable и имеет Naive/Offset; определение и его models принадлежат [F01](../features/F01-create-entity-schema.md#21-aggregates-entities-и-value-objects). `FieldDataType.DateTime` остаётся одним из 15 типов. Новые MVP fields используют Offset, historical definitions — Naive; Naive→Offset требует нового FieldId, изменение constraints само по себе его не требует. Source projection/normalized model/formal rendering сохраняют exact semantics, включая recursive Object/List Item. Для logical DateTime variant carrier `TemporalSemantics: Naive | Offset` обязателен; exact extension/CLR carrier ещё материализуется. Unknown/missing semantics не fallback в Naive/DateTime/object.

Offset означает instant с known UTC offset и использует `DateTimeOffset`. Formal mapping нового profile — JSON string `format: date-time` плюс CM strict 7digit/range/precision rules. Authoring parse принимает только invariant `yyyy-MM-dd'T'HH:mm:ss.fffffffzzz` либо UTC `yyyy-MM-dd'T'HH:mm:ss.fffffff'Z'`: ровно семь fractional digits, mandatory offset, whole minutes в ±14:00; local date и UTC instant должны быть в DateTimeOffset range. Missing offset, `-00:00`, leap second и local/UTC overflow invalid. Generic RFC3339/date-time validator не доказывает эти более строгие правила. Региональные timezone IDs/DST/schedules в первый MVP не входят; Date/TimeSpan и system/audit timestamps сохраняют смысл.

F04 authoring Save/read сохраняет исходный offset/7digits без server/browser timezone conversion. Publish Offset projection нового instance profile выдаёт UTC `yyyy-MM-dd'T'HH:mm:ss.fffffff'Z'` и сохраняет 100ns. 12:00 +03:00 и 09:00 Z дают same runtime bytes/hash при остальном равном; original offset остаётся в authoring snapshot, не runtime identity. Dynamic values хранятся в owner JSONB snapshot, а exact Published canonical bytes/profile/digest фиксируются отдельно атомарно Q19, без отдельных dynamic SQL timestamp columns.

Offset equality/comparison/inclusive Minimum/Maximum используют UTC instant. Bounds требуют offset; semantic schema hash нового profile пишет их в UTC, equivalent instant bounds разных offsets имеют same смысл/hash. Naive bounds остаются naive. List UniqueItems считает same instant разных offsets duplicate; Asc/Desc comparator даёт equal keys без offset secondary key и сохраняет authored tie order. Naive/Offset не сравниваются hidden timezone conversion. Copy по stable FieldId не превращает Naive автоматически в Offset: old removed value orphan, new Offset field unfilled, manual specialist transfer по F04.

Historical exact Naive generation остаётся `DateTime` Kind=Unspecified, Offset — `DateTimeOffset`. Optional properties → `DateTime?`/`DateTimeOffset?` по существующему presence rule; nullable CLR выражает отсутствие, wire null не становится допустимым. Explicit converters/shared pure temporal codec используют invariant parse/format с 7digits/100ns и runtime UTC Z для Offset без host timezone. Exact old/new versions должны генерироваться и компилироваться совместно в одном client project, с profile compatibility каждого exact input; old `/1` converter/bytes не меняются. Profile choice не становится UI selector. Whole new codec/metadata/identities/literal golden bytes остаются engineering Q19/Q31, OpenAPI/NSwag temporal union — Q15, SDK signatures — Q29.


### 2.6. TimeSpan


`TimeSpan`:


- JSON string;
- signed duration разрешён;
- canonical wire — invariant .NET `TimeSpan` `c` format;
- C# — `TimeSpan` через deterministic converter.


Zero и negative значения допустимы.


### 2.7. Enum


Enum definition хранит immutable string option keys, mutable authoring Name и monotonic Deprecated metadata.


Registry выражает allowed runtime strings через `enum`. C# profile генерирует настоящий enum type. Wire остаётся exact string option key через explicit serializer converter/attributes, а не numeric enum value.


Option `Name` не определяет C# identity. Deprecated option получает `[Obsolete]` в generated C#.


### 2.8. FlagEnum


FlagEnum runtime meaning — set string keys, не bitmask.


Registry:


- JSON array;
- items — allowed string option keys;
- duplicates запрещены;
- business order отсутствует.


C# profile использует `List<TGeneratedEnum>` как physical CLR container. `[Flags]` и numeric bitmask не используются. Serializer/canonicalizer сортирует значения по exact wire key для deterministic representation.


### 2.9. Color


Color wire — string `#RRGGBBAA`, ровно 8 hex digits после `#`. Canonical form uppercase hex.


Generated model не зависит от `UnityEngine.Color`. C# profile использует общий platform-neutral SDK type `RgbaColor`; Unity adapter преобразует его в Unity-specific representation при необходимости.


### 2.10. Object


Object создаёт отдельный generated `sealed class` в том же `.g.cs` exact root SchemaVersion.


Nested type naming строится детерминированно от immutable field keys/path. `Name` не участвует. Два похожих Object shapes не дедуплицируются эвристически: разные definition positions остаются отдельными generated types.


### 2.11. List


List → JSON array → C# `List<TItem>`.


Recursive definitions поддерживаются, включая `List<List<T>>` и `List<Object>`.


`OrderMode` сохраняется как `x-cm-order-mode` в `/1`. Он не меняет CLR collection type. MVP Q35 определил ItemValue scalar comparer и ObjectFieldPath comparer через ordered SchemaFieldId required Object nodes к required supported scalar leaf. Default требует отсутствующего comparer; Ascending/Descending проверяют authored array order, не сортируют. Equal keys допустимы без ItemKey/Guid tie-break. Exact new-profile metadata encoding остаётся открытым.

### 2.12. AssetReference


Schema definition AssetReference обязательно содержит `AssetKind`. Demo kinds:


- `Image`;
- `Audio`;
- `Video`.


Generated property использует общий platform-neutral SDK type `AssetReference`, а не `Guid` и не Unity-specific type.


Runtime descriptor v1 содержит server-confirmed immutable сведения, необходимые клиенту:


- `assetId`;
- `assetKind`;
- `contentType`;
- `sizeBytes`;
- `sha256Hash`.

Это ровно пять required properties в указанном порядке по owner F04/Q19. `FileName`, format/extension, dimensions/duration и URL не входят в runtime/formal descriptor. AssetReference JSON Schema запрещает дополнительные properties и закрепляет выбранный `AssetKind` через `const`.


`Bucket`, internal object name/ObjectKey, storage endpoint, credentials и provider URL отсутствуют.


CM-owned content URL не является сериализуемой identity formal content: SDK строит/получает read URL из CM configuration + AssetId. Submitted client metadata не становится authority; MediaLibrary остаётся source of truth.

При Publish F04 server захватывает descriptor из immutable confirmed MediaLibrary metadata в Published runtime snapshot; descriptor входит в values-only ContentHash. F13 читает эти bytes без повторного enrichment. Historical content не меняется из-за сегодняшней metadata projection/CM URL.


Exact field schema ограничивает `x-cm-asset-kind` одним required kind. F04/F13/F19 обязаны сохранить это binding.


### 2.13. MVP constraints: standard keywords и CM semantics

Source snapshot содержит typed definitions единственного владельца [F01 §2.1](../features/F01-create-entity-schema.md#21-aggregates-entities-и-value-objects); exporter/Core не создают независимую копию business models. List collection constraints и recursive Item definition передаются отдельно losslessly. Standard JSON Schema keywords применяются только при эквивалентной semantics:

| Rule | Возможное formal mapping нового profile | Условие / граница |
| --- | --- | --- |
| Inclusive Integer/finite Float/Decimal bounds | `minimum` / `maximum` | Значения сохраняют тип long/double/decimal, Decimal не проходит через double; intrinsic область не расширяется |
| String MinLength/MaxLength | `minLength` / `maxLength` | Unicode code points, supplementary emoji = 1, combining mark отдельный; no normalization; intrinsic max255 в тех же единицах |
| Integer/Decimal positive exact step | `multipleOf` при эквивалентной exact arithmetic | Без overflow/rounding/Decimal→double; generic library arithmetic требует conformance fixtures; Float MultipleOf отложен |
| List MinItems/MaxItems | `minItems` / `maxItems` | Non-negative min≤max; Required сам по себе не означает nonempty |
| List UniqueItems | `uniqueItems` только при доказанной эквивалентности; иначе CM extension | Full type-aware normalized equality Q19/Q35, Object FieldId/presence, FlagEnum set keys, nested List order; ItemKey/orphan/authoring metadata исключены |
| Text plaintext lengths | CM extension | Sanitized HTML после entity decoding: text nodes в document order без invented layout spaces/newlines; `<br>` не символ; semantic-empty и operational HTML cap отдельны |
| Date/DateTime/TimeSpan inclusive bounds | CM extension | Typed comparison в действующем temporal value profile; no dynamic now/today/relative/cross-field rules |
| List order/comparer | CM extension | Typed numeric/temporal, false<true, String/immutable Enum key UTF-16 ordinal; required scalar path Q35; no culture/casefold/natural sort/Name |

Text sanitize происходит до constraint validation/Save по F04, exporter и constraint validator не санитизируют Published text заново. Hash uniqueness индексирует кандидатов, а равенство подтверждается full normalized values/bytes; invalid/incomplete items дают issue без успешной proof. Comparer key equality не равна full item equality. Stable explicit UI sort сохраняет взаимный порядок equal keys и выполняет обычный Draft Save/If-Match; canonicalizer/Delivery/SDK не сортируют array. Unsupported direct Text/Color/FlagEnum/AssetReference/Object/List comparers, regex, Decimal Precision/Scale и Float MultipleOf вне первого MVP.

Generic Draft 2020-12 validator проверяет только эквивалентные standard rules. Text/temporal/comparer/особое equality требуют реального CM validator и profile-specific fixtures; успешная generic validation не доказывает extensions. Exact extension names/carriers/new-profile bytes остаются открытыми до golden implementation fixtures.


## 3. Deterministic Registry representation


Registry document bytes детерминированы одним Published snapshot + JSON Schema profile.


Правила v1:


- UTF-8;
- deterministic JSON property emission order;
- named SchemaField default order — `SchemaFieldId` по принятому comparator;
- option definitions — exact immutable Key ordinal;
- FlagEnum runtime canonical ordering — key ordinal;
- GUID — lowercase canonical `D`;
- никакого current timestamp, machine/user/environment metadata.


F03 `ContentHash` и Registry representation ETag — разные понятия.


- `ContentHash` относится к canonical CM schema content;
- Registry ETag относится к deterministic JSON Schema bytes конкретного profile.


Изменение Registry profile не переписывает historical F03 hash.

### 3.1. Literal Demo representation

Материализованный `cm-json-schema/1` использует compact UTF-8 без BOM, whitespace и final LF, strict Unicode и relaxed JSON escaping (`Utf8JsonWriter`/UnsafeRelaxedJsonEscaping). Object/List inline; `$defs` и `$ref` не нужны. Root emission order: `$schema`, `$id`, `x-cm-profile`, `x-cm-schema-id`, `x-cm-schema-version-id`, `x-cm-version-number`, `x-cm-schema-key`, `title`, затем Object `type`, `properties`, `required`, `additionalProperties`.

Named field emission: `x-cm-field-id`, `x-cm-field-data-type`, `title`, `description` только при non-null HelpText, `deprecated` (bool всегда), затем type/keywords. `required` array всегда присутствует и следует тому же ordinal lowercase Guid D order, что properties. Anonymous Item содержит `x-cm-field-data-type` и definition keywords без вымышленных ID/title/deprecated. Options: `enum` keys ordinal и `x-cm-options` array `{key,title,deprecated}`; FlagEnum ограничивает string items теми же keys, задаёт `uniqueItems: true` и сохраняет options metadata снаружи items.

DateTime `format: cm-naive-date-time` означает exact Naive seven-digit `yyyy-MM-dd'T'HH:mm:ss.fffffff`; TimeSpan `format: cm-time-span` — signed invariant `c`. Generic validator без CM format checker не проверяет их смысл. Color: `minLength=maxLength=9`, `pattern: ^#[0-9A-F]{8}$`. Integer baseline — Int64 bounds; это сохранение CLR/value meaning, не MVP configurable constraints. AssetReference uses lowercase D UUID pattern/length36, kind const, MIME nonempty string, positive Int64 size и lowercase hash pattern/length64.

Representation ETag — strong quoted lowercase SHA-256 exact document bytes. Source ContentHash/profile остаются отдельными internal metadata, не дополнительными formal properties/headers. HTTP отдаёт `Cache-Control: no-store`, только raw successful `application/schema+json`; ошибки — existing JSON ProblemDetails. Conditional 304 не вводится в Demo. Literal Boolean и all15 recursive fixtures находятся в F21 exporter unit tests; expected bytes/digests не вычисляются exporter-ом в assertion.

### 3.2. Локальный Demo operational profile

Согласованы explicit startup settings `ContentModeling:SchemaRegistry`: Profile=`cm-json-schema/1`, MaxBatchSchemas=64, MaxDocumentBytes=8388608, MaxBatchDocumentBytes=33554432, OperationTimeout=`00:00:30`. Дополнительно MaxSourceDocumentBytes=16777216 и MaxBatchSourceBytes=67108864 ограничивают input до materialization. Source preflight считает PostgreSQL `octet_length(content::text) + octet_length(canonical_content_bytes) + octet_length(published_content_json)` внутри того же read-only repeatable-read snapshot. Это отдельный input budget, не усечение schema и не подмена formal output limit.

Missing/unsupported profile, неположительные/overflow limits, batch меньше document и невалидный finite timeout блокируют startup. Числа — изменяемая environment configuration, не часть deterministic formal document; изменение cap не переписывает historical source hash или representation bytes. Отдельный выбранный F22 generation/file/archive profile находится в §7.2.1.


## 4. F21 read boundary


### 4.1. Public exact endpoint


Фиксируется endpoint:


```http
GET /api/v1/schema-registry/schema-versions/{schemaVersionId}
```


Успешный response:


```text
Content-Type: application/schema+json
```


Body — raw JSON Schema document, не `ApiResponse<string>`.


Lookup только exact immutable `SchemaVersionId`; fallback на latest отсутствует. Key-based aliases не нужны для canonical read.


Draft не является stable Registry target. Exact Published Retired/Withdrawn historical contract остаётся доступен tooling-у согласно staff/tooling policy; lifecycle не уничтожает formal history.


Demo endpoint anonymous вместе с остальным Demo. MVP developer/tooling access определяется staff/developer authorization и не смешивается с Unity entitlement/runtime license API.


### 4.2. Internal boundary


F22 получает formal documents через Application/public owner boundary в том же CM, без HTTP loopback.


Internal batch обязан вернуть coverage для каждого requested SchemaVersion либо failure. Нельзя молча пропускать один contract.


Public batch Registry endpoint для Demo не требуется.


## 5. C# generation profile F22


### 5.1. Profile identity


C# generator semantic profile v1 имеет identity:


```text
urn:vrschool:content-manager:csharp-generation-profile:1
```


Для краткой внутренней документации допустимо имя `cm-csharp/1`.


NuGet/package SemVer generator implementation и semantic profile version — разные вещи. Несовместимое изменение output semantics или обещанных deterministic bytes требует нового profile version.

Это правило относится и к `cm-json-schema/1`: несовместимое изменение formal representation вводит `/2`. Старый `/1` сохраняет возможность воспроизвести прежний результат для поддерживаемого exact input. Bugfix, меняющий обещанные generated bytes, также требует нового profile; обновление package SemVer само по себе не разрешает поменять bytes прежнего profile. Например, package `1.8.3` может реализовывать `cm-csharp/1`.


Demo UI не выбирает profile. Backend использует configured current supported profile. MVP CLI/config сможет pin-ить profile для reproducible builds.

MVP generator переносит typed constraints/comparer/TemporalSemantics contract metadata. Constraints сами по себе не меняют CLR types; отдельно согласованный Offset использует DateTimeOffset по §2.5. Hidden setter/constructor/converter constraint validation/coercion/default/clamp/round/dedup/sort не вводятся; explicit type/temporal codec conformance сохраняется. Validation остаётся CM validator responsibility. Если generated metadata/source/ZIP bytes изменились, обязателен новый `cm-csharp` profile; старый `/1` остаётся byte-identical. Exact attribute/metadata carrier и literal output нового profile **Уточняется**; они не выбираются из удобства Roslyn/JSON Schema adapter.


### 5.2. Generator architecture


`Schema.CodeGeneration.Core` принимает formal JSON Schema/profile input, а не Domain `EntitySchemaVersion` и не EF entities.


Рекомендуемая implementation:


```text
JSON Schema
  → validated normalized internal generation model
  → Roslyn SyntaxFactory
  → deterministic C# source
```


Универсальный NJsonSchema/NSwag schema-to-C# generator не является source of truth C# profile. CM generator владеет своими AssetKind, FlagEnum-set, temporal, naming, exact-version и SDK-binding semantics.


Для JSON Schema parsing/validation допустим library adapter. Реализация Demo использует строгий `System.Text.Json` parser фактического inline F21 `/1`: проверяет lexical token kinds, identities/metadata и intrinsic schema shapes всех 15 типов, отклоняет duplicate/unknown keywords, `$ref` и unsupported profiles без fallback. Для syntax generation используется `Microsoft.CodeAnalysis.CSharp` / Roslyn `4.14.0`, для выбранной serialization surface — Newtonsoft.Json `13.0.3`; pins находятся в central package management и не являются profile identity.

Физический Core — `contentmanager.api/src/BuildingBlocks/ContentManager.Schema.CodeGeneration.Core`, tooling `net10.0`, namespace `ContentManager.Schema.CodeGeneration.Core`. Production project не имеет references на SDK, Domain, EF, ASP.NET или Unity. Generated source использует C# 8 nullable surface; tooling TFM не является Unity runtime target. Public ABI и actual DTO определены один раз в [F22 §3.3](../features/F22-csharp-model-generation.md#33-dto-и-parameter-models).


### 5.3. Serializer profile


C# profile v1 использует **Newtonsoft.Json**.


Generated source содержит fully qualified `[global::Newtonsoft.Json.JsonObject(global::Newtonsoft.Json.MemberSerialization.OptIn)]` и `[global::Newtonsoft.Json.JsonConverter(typeof(global::ContentManager.Sdk.Client.DotNet.ContentModelConverter))]` на root/Object classes. Property получает exact-key `JsonProperty`, `Required.Always` для required либо `Required.DisallowNull` для optional; optional дополнительно имеет `NullValueHandling.Ignore`. `[global::ContentManager.Sdk.Client.DotNet.ContentField("<shape>")]` переносит recursive codec shape: scalar token, `Enum`, `FlagEnum`, `Object`, `AssetReference(Image|Audio|Video)` или `List(<item-shape>)`. `TypeNameHandling` не используется.

SDK converter проверяет required presence отдельно от CLR defaults, explicit null, unknown/duplicate wire members, exact numeric/temporal/enum/flag/asset codecs, intrinsic String nonempty/max255 и Text semantic nonempty. Optional CLR null при записи означает отсутствие свойства. List item types nonnullable; required reference property имеет initializer `default!`. Это codec/presence/intrinsic type-validity contract; authored setters не исправляют значения и не выполняют будущую generic constraint validation. Text sanitization остаётся до Save/Publish; codec не переписывает received Published текст.


System.Text.Json может быть отдельным будущим generation profile, но не тихой заменой поведения `cm-csharp/1`.


Unity 2022.3.62f3/AOT/IL2CPP compatibility проверяется реальным compilation/player test; наличие generated C# само её не доказывает.


### 5.4. Generated class shape


Profile v1:


- `#nullable enable`;
- обычные `public sealed class`;
- public get/set properties;
- parameterless construction;
- без C# `record`, `init` и language `required`;
- required reference property non-nullable и serializer validation;
- optional reference property nullable;
- optional value type → nullable value type.


Generated field property identity строится из immutable `SchemaField.Key` и всегда сохраняет exact JSON key через `[JsonProperty("<exact-key>")]`.


### 5.5. Namespace, root type и multiple versions


Каждая exact Published SchemaVersion может существовать рядом с другой version той же logical schema.


Namespace pattern v1:


```text
VRSchool.Content.Generated.<PascalSchemaKey>.V<VersionNumber>_<SchemaVersionId8>
```


`SchemaKey` берётся из frozen Published snapshot. `SchemaVersionId8` — первые 8 hex digits exact GUID в deterministic uppercase representation для C# identifier suffix.


Root type использует sanitized PascalCase frozen SchemaKey. Historical regeneration после rename logical schema даёт тот же namespace/type/file.


### 5.6. Identifier normalization и collisions


Property/member source identity = immutable field/option Key, не Name.


C# identifier normalization:


1. uppercase первого символа invariant с сохранением остальных допустимых символов key;
2. каждый run недопустимых identifier characters заменяется `_`, перед недопустимым начальным символом добавляется `_`;
3. Unicode format characters считаются недопустимыми: C# игнорирует их в symbol identity, поэтому они не должны обходить collision detection;
4. reserved root keyword получает prefix `_`; Windows device stems `CON/PRN/AUX/NUL/COM1..9/LPT1..9` case-insensitive также получают prefix `_` до namespace/type/file allocation (`con` → `_Con`, `__arglist` → `___arglist`);
5. collisions внутри type/member scope разрешаются независимо от enumeration/dictionary order; enclosing type name входит в reserved member names.


Если несколько field keys после normalization дают одно C# имя, каждый получает `_` плюс full uppercase `SchemaFieldId` GUID `N` (32 hex digits); reserved/invalid member name использует тот же suffix. Enum option collision получает `_` плюс full uppercase SHA-256 (64 hex digits) UTF-8 exact option key, поскольку отдельного option GUID нет. Все colliding candidates получают suffix; исход после suffix повторно проверяется, unresolved collision блокирует весь набор. Enum options сортируются ordinal по exact key и получают explicit integer assignments `0..N-1`; `[EnumMember(Value="<exact-key>")]` сохраняет wire string.


Никакого «первый встретившийся победил» поведения нет.

Nested Object types получают deterministic имя от пути immutable field keys, например `Address`, `AddressCoordinates`, `ItemsItem`; `Name` не участвует. Коллизии этих имён разрешаются stable suffix от `SchemaFieldId` соответствующей definition position. Одинаковый shape в двух позициях не является основанием дедуплицировать types.


### 5.7. SDK binding exact version


Root generated class получает platform-neutral SDK attribute `global::ContentManager.Sdk.Client.DotNet.ContentSchemaAttribute`, public constructor `(string schemaId, string schemaVersionId, int versionNumber)`, где GUID arguments — lowercase canonical `D`:


```text
ContentSchema(SchemaId, SchemaVersionId, VersionNumber)
```


Он однозначно связывает `T` с exact representation F19 typed storage/sync. Binding не выполняется по class name либо latest schema.


Property-level SchemaFieldId attribute не обязателен profile v1: wire property binding использует exact field Key, а formal Registry сохраняет field ID metadata.


### 5.8. Deprecated


Deprecated SchemaField обязательно генерирует `[Obsolete]` property.


Deprecated Enum/FlagEnum option обязательно генерирует `[Obsolete]` enum member.


Deprecated остаётся formal contract/migration signal и не удаляется автоматически.


## 6. Deterministic source и ZIP


### 6.1. Source bytes


Generated `.g.cs`:


- UTF-8 without BOM;
- LF (`\n`);
- final newline обязателен;
- invariant culture;
- fixed первые строки `// <auto-generated />` и `#nullable enable`, затем Roslyn four-space LF namespace/declarations;
- никаких timestamps, usernames, hostnames, machine paths и случайной metadata.


Одинаковый formal input + тот же `cm-csharp/1` → byte-identical `.g.cs`.


### 6.2. File names


Один root exact SchemaVersion создаёт один `.g.cs`, содержащий root и его nested generated types.


Pattern:


```text
<PascalSchemaKey>.V<VersionNumber>.<SchemaVersionId8>.g.cs
```


Несколько exact versions одной schema не конфликтуют.


### 6.3. ZIP bytes


ZIP также deterministic:


- entries отсортированы ordinal;
- DOS entry timestamp `1980-01-01 00:00:00` (time `0`, date `33`);
- classic stored ZIP, compression method `0`; no ZIP64/data descriptors;
- UTF-8 names, flag `0x0800`, version-needed `10`, central creator/version-made-by `20` (DOS platform), attributes/disk fields `0`;
- CRC-32 и compressed/uncompressed sizes пишутся явно, offsets следуют ordinal entry order;
- local/central extra fields и comments отсутствуют; archive comment отсутствует;
- одинаковый generation request semantic set → byte-identical ZIP.


Request ordering не влияет на source/ZIP ordering.


## 7. Generation HTTP API


### 7.1. Endpoint


Фиксируется:


```http
POST /api/v1/code-generation/csharp
```


Demo request содержит только список exact `SchemaVersionId`.


UI не отправляет namespace, serializer, profile options, arbitrary code template либо source text.


### 7.2. Request validation


- empty selection → `400`;
- duplicate SchemaVersionId → `400`, server не делает silent `Distinct()`;
- порядок request IDs не влияет на generated artifact;
- каждый ID должен разрешиться в допустимый exact Published contract.

Core сначала разрешает весь requested set, затем обходит root schemas по ordinal comparison lowercase canonical GUID `D` для `SchemaVersionId`. Пользовательский порядок selection не становится порядком генерации. ZIP entries после этого отдельно сортируются ordinal по filepath.


Configurable guardrails обязательны: maximum selected schemas, formal input bytes, generated source/files/archive size и operation timeout. Registry source/formal числа согласованы для локального Demo в §3.2; F22 использует отдельный выбранный operational profile ниже. Это environment/quality configuration, не semantic profile bytes; performance/load ceiling этим не доказан.

### 7.2.1. Локальный Demo F22 operational profile

Section `ContentModeling:CSharpGeneration`: `Profile=cm-csharp/1`, `MaxSelectedSchemas=64`, `MaxInputBytes=33554432` (32 MiB), `MaxFiles=64`, `MaxFileBytes=4194304` (4 MiB), `MaxSourceBytes=33554432` (32 MiB), `MaxArchiveBytes=41943040` (40 MiB), `OperationTimeout=00:01:00`. Server Core limits дополнительно устанавливают recursive `MaxDepth=64`. Thresholds явные, без implicit production defaults.

Startup отвергает unsupported/missing profile, nonpositive/overflow byte/count limits, files меньше selected count, source меньше file, archive меньше source и invalid/nonfinite timeout. Core валидирует свои positive limits и считает formal input bytes до owned snapshot; output UTF-8 writer ограничен per-file и remaining whole-source budget. ZIP preflight ограничивает count/input/archive bytes до completed archive allocation. Deadline связывает F21 read, Core и ZIP; caller cancellation отличается от own timeout. Отдельные F21 source/formal caps и его read/export deadline сохраняются, не подменяются F22 settings. Изменение thresholds не меняет `.g.cs`/ZIP bytes для допустимого exact input.


### 7.3. Complete result


Generation — **all-or-error**.


Если одна requested SchemaVersion отсутствует, invalid, unsupported или генерирует fatal error, успешного ZIP нет вообще. Partial ZIP запрещён.

Непубликованная версия, invalid/unsupported formal contract и неразрешённая после deterministic suffix collision также блокируют весь request. Coverage должна содержать ровно одну root binding для каждого requested ID, без пропусков, повторов или посторонних targets.


Core result содержит coverage минимум:


- requested SchemaVersionId;
- generated root CLR type;
- generated filepath.


Wrapper проверяет exact coverage для всего requested set перед формированием success.


### 7.4. Diagnostics


Generator diagnostics имеют severity:


- `Info`;
- `Warning`;
- `Error`.


`Error` блокирует artifact. `Warning`/`Info` не блокируют complete output. Machine diagnostic code стабилен внутри generation profile; human-readable text не является единственным machine contract.


Demo ZIP не обязан содержать `generation.json`/manifest только ради warnings. Обязательный ZIP manifest не вводится.

В Demo успешный ZIP содержит generated source files. `Info`/`Warning` остаются в Core result и серверной диагностике; их передача через HTTP metadata/header либо отдельный preview API не обязательна и относится к последующему tooling. UI не обещает отображение отсутствующей success diagnostics metadata.


### 7.5. Response


Успех:


```text
Content-Type: application/zip
Content-Disposition: attachment; filename="content-manager-csharp-models.zip"
```


Перед началом binary success server полностью:


1. разрешает все exact contracts;
2. получает F21 formal representation через in-process boundary и валидирует/нормализует весь formal input;
3. генерирует все source files;
4. проверяет coverage/diagnostics;
5. строит complete deterministic ZIP.


До начала binary response ошибки возвращаются обычным согласованным ProblemDetails/API error profile. После начала ZIP transfer JSON error внутрь binary stream не вставляется.


### 7.6. Cancellation и persistence


Generation stateless. ZIP/source не сохраняются в БД/S3 как jobs/artifacts Demo.


Cancellation до готового artifact прекращает request без persistent partial result. После начала transfer client disconnect прекращает передачу; resume protocol не вводится.


Повторный request безопасен как read-only deterministic generation.

## MVP CLI: конфигурация и файловый workflow

**Ответ:** пользователь согласовал все 22 пункта. Normative модели, adapters и algorithms принадлежат [backend F22](../features/F22-csharp-model-generation.md#82-mvp-cli); бизнесовый workflow — [F22](../../../business/features/F22-csharp-model-generation.md#mvp-cli-workflow). Это target contract, не созданный tool package/работающий CLI/пройденные filesystem tests.

### Поставка и конфигурация

1. Local .NET tool поверх того же Core; version pin в `.config/dotnet-tools.json`. CLI не runtime SDK dependency и не нужен на Unity device.
2. Package `ContentManager.Schema.CodeGeneration.Cli`; command `cm-schema`.
3. Единственное имя project declaration — `content-manager.json`; `content-schemas.json` не alias/второй источник.
4. Configuration: format version, CM address, generated output directory, exact SchemaVersionId list и explicit C# generation profile каждого input. No latest/current SchemaKey lookup/automatic selection update.
5. Relative paths от configuration file; `--config`, иначе файл только в current directory, без parent search.
6. Empty selection, duplicate IDs, unknown format/options — ошибки.

### Команды

7. `restore` получает/проверяет formal inputs; `generate` генерирует из locked local inputs; `check` readonly сравнивает expected/current output. У всех `--config`; check ничего не пишет.
8. Generate offline, restore выполняется отдельно; hidden network fetch из build/generator не вводится.
9. Первый restore создаёт lock, обычные соблюдают existing lock. Selection/profile change требует `restore --update-lock`, без latest.

### Воспроизводимость

10. `content-manager.lock.json`: exact IDs, formal/generation profiles, SHA-256 formal bytes, expected filenames/source hashes. Tool package version отдельно в standard tool manifest.
11. Original formal bytes в `content-manager.schemas/<sha256>.json`, без reserialization; config/lock/documents рекомендуется хранить в Git для offline reproduction.
12. CLI independently hashes downloaded bytes, проверяет exact document identity/profile и lock; ETag не заменяет checksum. Mismatch ordinary restore — error, не silent recapture.
13. Core проверяет compatible profiles; unknown/incompatible blocks whole set, no fallback. Новые MVP profile identities/bytes всё ещё Q19/Q31, не назначены этим блоком.
14. Full resolution/generation/collision/coverage до publication; preparation failure сохраняет existing lock/source.

### Владение файлами

15. Собственный каталог actual generated paths/hashes; update/remove только owned files. Auto-generated comment не ownership proof.
16. Manual edit прежнего source либо foreign new target path — conflict, без первого `--force`.
17. Dependency removal удаляет только её unchanged owned sources после successful generation. Foreign files/Unity `.meta` не удаляются; existing source update сохраняет `.meta`.
18. Staging + recovery journal; failure recovery, next modifying call сначала resolves unfinished operation. Exclusive project/output scope lock для CLI writers. Whole-set atomic visibility compiler/Unity Editor не обещается, generate завершается до build/import; third-party changes during recovery — explicit conflict.

### CI, доступ и проверки

19. Check повторно invokes Core, сравнивает exact bytes/set/coverage и ownership: changed/missing/extra owned file failure; matching success без writes.
20. Generated `.g.cs` первого workflow в Git; разработчик regenerates явно, CI check → compile. Automatic Editor plugin/MSBuild source generator не добавляются.
21. Registry staff/developer authorization, не activation keys/DeliverySession. Credentials не config/lock/command arguments. Exact console login отдельно [Q24](../../frontend/questions/Q24-admin-sign-in.md#developer-tooling-доступ-cli), existing browser cookie не достаточное решение.
22. Acceptance: same Core bytes server/CLI, offline, twoexact/all15, profile mismatch, manual edits/owned cleanup, concurrent process/crash recovery, Unity `.meta` preservation и actual compile.

Config/lock/ownership/journal модели описаны один раз в [F22 §3.3.1](../features/F22-csharp-model-generation.md#331-mvp-cli-локальные-модели-проекта). Commands/algorithms/DI/filesystem boundaries там же; CLI не создаёт новые CM tables/HTTP generation endpoints/runtime inventory. [Q32](../../frontend/questions/Q32-sdk-package-distribution.md#mvp-cli-поставка-tooling) фиксирует actual packaging/install dependencies отдельно от SDK base train.

Остаются exact JSON/error/exit/journal literals и actual filesystem/platform/feed/CI fixtures; developer-tooling auth и новые MVP profiles — отдельные архитектурные блоки. Demo остаётся UI/API/ZIP и не требует CLI.
