# MVP

[Каталог milestones](../README.md) · [Предыдущий milestone: Demo](../demo/demo.md) · [Следующий: Production](../production/production.md).

## Цель и база

После Demo и обратной связи реализовать согласованный продуктовый процесс управления контентом, Publishing и защищённой выдачи. Базовая цепочка Demo сохраняется, но исключённые из Demo сотрудники, интеграции, каталог и лицензионные права становятся частью MVP. Этот состав не обозначает готовность реализации, даты или законченные технические profiles.

## Сопровождающие и не назначенные фичи

[F20](../../business/features/F20-unity-demo-scene.md) сохраняется как отдельный SDK example/demo consumer. Использование и развитие по feedback уточняются; сцена не превращается в runtime dependency SDK или обязательный игровой интерфейс продукта.

[F23](../../business/features/F23-unity-addressables.md) optional; milestone первой реализации не назначен. Unity Editor codegen tools/source generators/incremental build/CI integrations, дополнительные SDK других языков и расширенная F14 не объявляются обязательными MVP только из архитектурной расширяемости. CLI F22 уже принят и не переносится в Production как впервые появляющаяся функция.

[Q31 CLI](../../technical/backend/questions/Q31-schema-code-generation.md#mvp-cli-конфигурация-и-файловый-workflow) закрывает 22 пункта configuration/tool commands/reproducibility/owned filesystem/CI acceptance. Generated sources в Git, CI check → compile; .meta/foreign/manual файлы не удаляются, whole-set atomic import/build не обещается. Exact tool runtime/feed/codec/exit/journal и real crash/concurrency/Unity compile результаты ещё требуются. Console staff/developer authorization [Q24](../../technical/frontend/questions/Q24-admin-sign-in.md#developer-tooling-доступ-cli) и whole new MVP profiles Q19/Q31 отдельно; не считать согласование CLI доказательством готового protected tooling.

## Межфункциональные границы

### Предложенный интеграционный объём доставки ассетов

По [Q37](../../technical/frontend/questions/Q37-launcher-asset-delivery.md) приняты schema-owned DeliveryMode (OnDemand default / Preload / RequiredBeforeLaunch), entity sync Launcher и app on-demand через общий SDK cache. Их реализация относится к этапу после самостоятельного Demo. Источник предлагает MVP integration: versioned field metadata в F01–F03/F21, resolved exact AssetDeliveryManifest в F13, build-to-Variant/SchemaVersion mapping, два процесса Launcher/Unity с общей SQLite metadata и файловым кэшем F19, readiness и basic preloads. Это рекомендуемое распределение, не утверждение всех новых функций обязательными MVP.

Точные profiles/DTO/manifest API, сохранение FieldId при смене режима, credential re-admission, native provider/locks и operational limits остаются Q37. Optional F23 не назначается в milestone автоматически. Runtime AssetReference/F13 wire v1 и исторические hashes сохраняются; нет global MediaAsset policy и отдельного режима клиента, редактируемого в SQLite.

IdentityAccess по [Q24](../../technical/frontend/questions/Q24-admin-sign-in.md#принятый-протокол-identityaccess-и-восстановления-формы) изолирован от лицензий/Delivery и не зависит от общего UI/API host. Blazor Standalone UI и API независимо размещены на HTTPS-поддоменах одного base domain: credentialed exact-origin CORS/host-only API cookie/antiforgery. Defaults staffSession8h/setup20min/password15–128/lockout5failed15min configurable; last-ready-admin guard/one-use setup/provider coordination и in-memory open-tab recovery приняты. Reload/close/browserrestart не входят в recovery guarantee; MFA/custom-role editor/direct grants отложены. Final wire/provider/keyring/config/migrations и реальные browser tests остаются engineering, Demo scope не расширяется.

F12 требует immutable Publishing PolicyAgreement **до** source confirmation CM-content периода. VR School durable plan → authenticated CM agreement call вне source transaction → conditional same-plan confirmation+outbox. Это новая зависимость оформления CM-content права от CM; application-license/Project Storage независимы. Agreement не даёт прав до confirmation и не истекает автоматически в MVP. CatalogAccess хранит confirmed source facts/current period/completeness, Delivery — own exact binding; renewal/correction и strict multi-license unknown определены в [Q20](../../technical/backend/questions/Q20-persistence-and-migration.md#f12-policyagreement-и-подтверждение-периода). Session/lease и confirmed-visibility semantics выбраны Q16/Q17, physical/wire детали остаются engineering. Scope Demo не расширяется.

Publishing workflow фиксирует immutable promotion inputs/applied membership и per-item tokens/intent. Automatic prepare revision+moderation+binding атомарен в Publishing; human decision/activation раздельны, late Approval защищён Product state Version/Variant Sequence/current head. Manual no-op и exact Cancel имеют разные последствия. ClientOperationId replay сохраняет original confirmed receipt; new intentional artifact разрешён даже при том же content. F09 empty releases допустимы, F10 final nonempty обязателен; current effective closure и historical retention различаются. [Полный workflow](../../technical/backend/questions/Q20-persistence-and-migration.md#publishing-workflow-capture-и-продолжение).

Для коротких взаимозависимых mutations принят [общий MVP PostgreSQL consistency guard](../../technical/backend/questions/Q20-persistence-and-migration.md#mvp-протокол-consistency-guard): один transaction-level key во всех репликах, own Read Committed transaction, acquire до fresh facts/row locks и owner commit. Foreign public reads independent primary scope без общей BC transaction; все invalidating writers/receivers/workers/setup участвуют. Long I/O/user/projection waits вне gate. Приёмка включает real PostgreSQL races/faults и измерение wait/held duration; Production throughput не считается доказанным. Demo сохраняет прежний one-process AssetId guard.

F06/F15 используют внешние source facts, но CM не становится владельцем Product/ProductVariant. F07–F11 формируют full product publication; ContentModeling Published schema/instance не равны ProductVariantPublicationRevision. F17 модерирует revision, не каждую схему или экземпляр отдельно.

[Q35](../../business/questions/Q35-value-constraints.md) определяет первый MVP набор typed constraints. Schema Save отклоняет invalid definitions; Instance Save отклоняет новый intrinsic type-invalid ввод, но сохраняет type-valid дополнительные нарушения с адресуемыми issues. Publish строго проверяет весь snapshot без partial result/исправлений. Copy переносит совместимые values по stable FieldId без orphan только из-за constraints. List сохраняет authored order; canonicalizer/Delivery/SDK не сортируют его автоматически. Regex, Float MultipleOf, Decimal Precision/Scale и расширенные comparers отложены; Demo не расширяется.

[Q34 DateTime MVP](../../business/questions/Q34-schema-field-semantics.md#datetime-mvp-temporal-semantics-и-совместимость) фиксирует Offset как UTC instant с известным offset, без regional timezone/DST. New definitions — Offset, historical — Naive; смена immutable TemporalSemantics требует нового FieldId. Save/read сохраняет original offset и 100ns precision, Publish проецирует UTC с семью fractional digits и `Z`. Equality/bounds/UniqueItems/order работают по instant, different offsets одного instant равны без offset tie-break. Copy только по FieldId: старое removed Naive value orphan, новое Offset field незаполненное; перенос и offset задаёт специалист вручную. Date/TimeSpan и system timestamps сохраняют смысл.

Catalog Archive ограничивает новую работу и допускает agreed limited maintenance/safety actions; materialized revisions и действующие подтверждённые права не отменяет. Restore не auto-activates/unwithdraws/grants. Repair commit не означает применённый move и не создаёт публикацию. V2 mapping/receive-work/fault/reconciliation protocol выбраны Q23; конкретные codecs/SDK enlistment/DDL/transport settings и exact repair wire остаются инженерной детализацией Q23/Q15/Q20, а не скрытой зависимостью Demo.

Publishing ActiveRevisionId и Delivery-effective state различаются. F13 фиксирует целый exact snapshot/history после готовности materialization; старый pinned session не пересобирается по сегодняшнему контенту. Assets остаются самостоятельным gateway read с membership/current hard restrictions до output cache/304/range/proxy. YARP не отменяет F12/F13/F16 security.

Archive authoring objects ограничивает новую работу при сохранении historical references; Retire и Withdrawal имеют свои согласованные назначения. Restore/hard-delete/retention matrix уточняется в owning F/Q. Не переносить permissive Demo режим в protected MVP.

## Приёмка и открытая детализация

[Q19 canonical v1](../../technical/backend/questions/Q19-content-hashes.md#принятый-canonical-profile-v1) закрывает six source/runtime/manifest/group/inventory/plan profiles, SHA-256/string/numeric/order/presence rules. F10 runtime manifest excludes provenance/artifact/approval context, F13/SDK checks actual installed/full target and original plan; atomic bytes/profile/digest retain history. Same pure library/typed metadata and [literal samples](../../technical/backend/canonical-v1-vectors.md) require actual backend/Unity conformance, not architecture text. Первый новый MVP profile set совместно включает constraints Q35 и Offset Q34: новые schema-content, instance-content, JSON Schema и C# profiles обязательны. cm-instance-content/1 недостаточен для новых Offset runtime bytes. Исторические `/1` bytes/Naive read не rehash/re-export. Group/inventory/manifest profiles меняются только при собственном layout/semantics change и сохраняют content-profile identifiers. Temporal semantics закрыты; exact whole new-profile codec/extension carriers/literal golden bytes ещё **Уточняется** Q19/Q31, готовый `/2` codec не назначен. Q33 exact sync envelopes remains separate; no new Demo licensing/Publishing prerequisite.

Приёмка Q35 включает Unicode/String/Text length, exact Decimal и inclusive bounds, recursive definitions, Object duplicates с разными ItemKey, equal comparer keys/stable sort, Save/Publish/Copy и old/new-profile fixtures. DateTime acceptance дополнительно покрывает offset date rollover, ±14:00/local и UTC range overflow, 100ns precision, equivalent instants/bounds/unique/ties, Copy/orphan и совместные historical/new generated versions. Registry Offset использует format:date-time и CM precision/range checks; generic JSON Schema validator не доказывает CM extensions. C# historical Naive остаётся DateTime Kind=Unspecified, Offset — DateTimeOffset; constraints metadata не вводят hidden setter validation/coercion. Эти требования не подтверждают code/tests/Player conformance или выбранные bytes новых profiles; OpenAPI/NSwag temporal union и SDK signatures остаются engineering Q15/Q19/Q31/Q29.

F18 activity scope/granularity/read policy/filter/keyset/default50/max200/retention согласованы в [Q10](../../business/questions/Q10-permissions-and-isolation.md#f18-history-scope-и-visibility). Source business commit+durable normalized intent и separate audit append/inbox должны пройти real crash/ACK/duplicate/failure tests; source success не ждёт audit row. Common history для Specialist/Administrator, staff-management history только Administrator; dictionary/page visibility before rows/cursors. UTC occurred/recorded times не global causal order, cursor не fixed snapshot; manual refresh. Full content/secrets/before-after и security failures не business journal; UI readonly/no export/realtime/automatic purge. Physical mapping/transport/codecs ещё Q15/Q20, Demo scope не расширяется.

Protected runtime [Q16](../../technical/backend/questions/Q16-activation-and-sessions.md#принятый-протокол-сессий-и-response-leases) принят: отдельная CmDeliverySession с opaque Bearer/verifier и коротким encrypted original creation replay через shared persistent protected keyring. Configurable defaults: absolute TTL 30 минут, replay 5 минут, validation attempt 30 секунд, response lease 5 секунд. CM monotonic attempt включает HTTP, crypto и gate wait; selected credential epoch и required license watermark проверяются до admission. Raw activation key/hash не сохраняются и не публикуются; Session verifier и encrypted replay exception имеют отдельные границы. Новый CurrentPeriod, pinned Freeze mismatch либо known incompatible correction требуют нового admission без repin/restore; required unknown даёт временный DataNotReady. Короткий guarded checkpoint предшествует cache/304/Range; независимый monotonic deadline прекращает transfer при stalled renewal. Физический пятисекундный network SLA и отзыв уже переданных bytes не обещаются. Exact wire/source/crypto/keyring/timer/Host/retention детали и реальные SQL/YARP/storage tests остаются; anonymous Demo не расширяется.

Для F13 принят [confirmed-visibility profile](../../technical/backend/questions/Q17-publication-availability.md#подтверждённая-видимость-и-история-delivery): full committed effective state и saved primary observation VisibilityConfirmedAt различаются. Freeze strict < UpdatesUntil; late confirmation исключается, necessary pending/incomplete history Indeterminate. Source catch-up строго ordered, каждый actual effective transition отдельным owner commit, known terminal intermediate — NotEffective без fake history; exact ban независим от snapshot/pointer. Приёмка включает PostgreSQL cutoff/crash/ACK/gap/replay/clock/null/rollback/ban tests. Concrete adapters/wire/DDL/DI и measured source/network lag ещё открыты; Q16 session/lease semantics уже выбраны, Demo не расширяется.

Нужны реальные проверки full source→catalog/publishing→effective delivery, staff/moderation/history и protected client behavior, включая races/history/rollback/revoke/withdrawal и восстановление SDK. App/DB tests с doubles не подтверждают VR School/broker/storage/Unity integration. Конкретные contracts/security/provider/TTL/limits/время effective visibility определяются F/Q, не milestone-таблицей.
